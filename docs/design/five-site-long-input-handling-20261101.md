# 五站长输入处理方案：Actor、Skill Generator、Teacher

创建：2026-11-01；修订 16（2026-11-10）；状态：方案与分阶段验收并存。本次明确策略/3有限候选前缀及执行历史/2；可用首屏、统一动作/读取提示、拒绝反馈和效果评价合同保留；已有窗口、读取、送达和所选Actor绑定合同保留。Map/Admin均在范围内，按结构和实际消费者验收；实施交接见专项目录（workspace 材料，未发布）。设计要求及候选数值不代表已经实现、存在对应运行Bug或改善行为。Actor统一64K，A100也不例外；输出4,096且禁减档。Generator不扩容；本页不授予旧请求重发或跨作业续跑能力。

## 1. 目标与已有事实

适用 shopping_admin、shopping、gitlab、reddit、map。目标是让长输入有明确处理路径，同时保留 Actor 作出正确操作所需的信息，以及 Teacher 提炼正确 skill 所需的证据。输入超限按下述有界路径处理，无法容纳必要事实时明确容量缺口。

复用[原五站压缩方案](five-site-context-compression-v1.md)、对比审查（workspace 材料，未发布）和现有 context/engine/ledger。原方案继续负责已实现压缩与来源核验；本页定义超限后的预算、窗口和按需读取合同。当前模块过门即随原合格题目批次收真实效果，不增加五站压缩整体预跑、默认配对双调用或重复 SFT。

| 已有事实 | 设计含义 |
|---|---|
| Map 全 ID 样本为 30,825 tokens，原输入门 28,672 | 单页即可超限，减少历史轮数不能根治 |
| 缩进实验（workspace 材料，未发布）：两空格 30,825；一空格 30,824；制表符 33,218 | 保留当前缩进，不重复这项实验，不以字符量估算 token 收益 |
| 原Map样本的历史Qwen2.5-7B-Instruct配置窗口32,768，输出4,096 | 28,672只属于原冻结请求；现行Actor目标64K/O4096，不回写历史 |
| Generator 已有引擎记录（workspace 材料，未发布）：Qwen3-8B 配置 40,960，实际检查是短输入 | 配置数不等于满窗口质量/压力验收，不把它称为已验长输入能力 |
| Teacher 是独立远程模型；旧计划存在输入配置与旧执行不一致 | 按实际路由、输出/推理、计数与费用独立定限，不能假定无限或沿用 Actor 上限 |
| 当前本地加载器拒绝未经验证的 RoPE 扩展 | 扩窗口需要配置、加载、资源和消费者共同接通，不是只调大 max_input_tokens |

运行时以各角色实际冻结的配置和源码回执为准，不把本页当作新的 current 清单。原 Map unknown 不重放、旧证据不回写；运行树及原请求配置保持冻结。

## 2. 按超限来源处理，不按网站复制五套算法

| 类型 | 典型来源 | 首选处理 | 不适合的处理 |
|---|---|---|---|
| 单份观察过长 | 商品/订单表、代码或 diff、评论树、地图数据、异常诊断页 | 保守结构整理；合格长窗口；必要时按语义区域读取 | 只减历史轮数、直接删尾 |
| 历史累积过长 | 多页查询、反复编辑、长流程 | Actor 近期完整交互＋仍有用的公开事实记忆 | 机械只留最后 N 轮、把失败动作去重成一次 |
| 多尝试证据膨胀 | Teacher 多候选、多轮修订/复验 | 精确正文共享、完整事件与因果关系、Teacher 独立窗口 | 裁成 Actor 最近几轮、只保留成功轨迹 |
| 模板/格式冗余 | 重复工具说明、空包装、相同协议 | 开发时离线选定简洁表示，冻结格式 | 每次请求重测所有编码，复杂缩写或自由摘要 |
| 配置/计数异常 | 错 tokenizer、旧模板、路由变化、估算偏差 | 拒绝发送并定位配置/计数错误 | 当正常长输入反复扩窗口 |

分项统计用于诊断。tokenizer 存在跨边界合并，组件单独 token 数不一定可相加；最终准入必须计完整请求与实际模板。

五站具体保护要求如下。所有结构转换须保留作用范围、顺序、身份和来源，不能只按关键词留下看似相关内容。

| 网站 | 常见长内容 | 必须保留的关系 |
|---|---|---|
| shopping_admin | 商品、订单、属性和操作表 | 行与记录身份、控件归属、值/单位、保存反馈、其他记录保护 |
| shopping | 搜索结果、商品介绍、订单历史 | 查询条件、商品/订单身份、价格币种、日期、变体和可见结果 |
| gitlab | 代码、diff、issue、项目/Group 列表 | 路径/行号、代码缩进、增删标记、评论/作者、权限和对象范围 |
| reddit | 深层评论、帖子列表、媒体 | 父子评论、作者、正文/媒体对应、回复对象、时间和动作返回 |
| map | 路线、地点、空间数据、错误页 | 坐标/单位、道路与路线关系、图层状态、控件 ID、错误与恢复入口 |

这些是覆盖目标，不声称已验全部网站/任务族。具体保护由原任务合同和现有判定语义决定，不新增全站统一 Judge。

## 3. 超限后的分层处理路径

### 3.1 角色预算独立，发送前选择一次

复用现有 BudgetProfile：`C` 为已验证窗口，`I` 为配置/服务输入上限，`O` 为输出预留，`M` 为可信的未计开销；令 `H = min(I, C - O - M)`。若服务对推理 token 另有规则，应冻结其准确语义，避免漏算或重复计算。完整输入计数 `N <= H` 才能发送。远程估算必须有可信上界；不能把经验乘数冒充 exact。

软阈值只触发已选整理策略，不能仅因超过软阈值拒绝仍满足硬门的输入。第一阶段不要求重新寻找通用最优阈值。

每个角色只配置有限的有序档位，例如现行 standard 与经验证的 long。候选档位包括模型/权重/模板/计数器、窗口、输出预留、资源与费用范围。它们是同一角色的明确配置，不允许任意替换成 Teacher 或更强模型。

处理流程：

1. 核来源和原请求状态；已有 dispatch/pending-unknown 的请求先走原恢复核查，不进入换格式重发流程。
2. 采用已冻结的确定性整理策略；可缓存的内容复用。默认生成一个选定表示，不在每次请求比较一堆缩进/编码。
3. 计最终完整输入。Actor先按[自适应观察规则](#adaptive-observation)选择紧凑全页或合格局部视图，不能只因低于硬上限便绕过已启用的整理/范围选择；最终能容纳且保护核验通过时保存输入/配置/计数/变换回执，交给原一次发送账本。
4. 若不能容纳，在首次派发前选择范围内且已验证的 long 档位；tokenizer/template 改变时重新组装和计数。
5. 对已支持的 Actor 分区读取或事实记忆采用相应策略；没有该能力的任务登记具体容量阻断，不删证据、不伪装 task failure。
6. 每次准备最多尝试配置中明确列出的有限档位；全失败则退出，禁止压缩/扩窗口无限循环。

不同站点使用相同调度规则。单题容量阻断不阻塞无依赖的合格任务继续运行。任务总轮数/总 token/费用/时限与单请求窗口分别管理。

### 3.2 固定输出预算与输入准入

Actor统一总窗口65,536、输出预留4,096，输出减档禁用。完整输入须同时满足 `N <= I` 和 `N + 4,096 + M <= 65,536`；M=0时最大输入为61,440。仍超限时采用已支持的结构读取或事实记忆，必要信息无法容纳则记录容量阻断。Generator与Teacher使用各自冻结预算及独立计数。

配置沿现有BudgetProfile/参数引用绑定角色、模型、tokenizer/template、C/I/O/M、资源及验证回执；缺精确资格拒绝启用。输出length或结构不完整保留原响应并按原异常合同处理，已派发/unknown请求不换配置重发。

### 3.3 Actor 64K部署与资源资格

Generator保留现行模型/窗口与独立计数，共用代码变化只补直接受影响兼容检查。

Actor统一64K（65,536），包括A100。现有A40资格按精确配置复用，其他实际采用的GPU/环境仍核兼容性；MIG不纳入默认长窗口资源。

64K指输入与输出合计上限。维持输出预留4,096、未计开销M=0时，输入上限为61,440；实际仍取`min(I, C-O-M)`。调度绑定实际GPU型号及精确配置验收记录。已有A40实际资源与运行接线资格见运行验收（workspace 材料，未发布），此次MapData真实使用64K、单轮输入峰值2,730见业务记录（workspace 材料，未发布）。这不证明全部题目容量或质量已通过；历史32K冻结作业不改，运行中OOM不自动换档重发。

复用现有引擎/worker，显式配置位置编码、窗口、dtype、attention后端、输出预算及资源需要。保持原标准档位可复用，长配置不能污染标准会话/缓存。资源调度遵守现有同节点资源约束，不要求两个档位的权重同时常驻。

验收只覆盖变化的加载/计数/预算/监督接口及必须的真实长输入运行：模型是否加载、是否无截断处理完整输入、峰值显存/处理时间是否在预算内、输出能否正常结束、失败后是否正确关闭。真实语义效果随原合格题目批次确认；初次改变模型位置编码所必需的真实运行检查不能用 mock 代替，也不扩为五站整体重跑。

Actor 的模型参数、KV 推算、各 GPU 的条件上限、预填充峰值及 CUDA 兼容限制见显卡容量估算（workspace 材料，未发布）。该报告是资源估算，部署资格仍以精确配置回执为准。

官方背景：[Qwen2.5-7B-Instruct 长文本说明](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct#processing-long-texts)、[Qwen3-8B 长文本说明](https://huggingface.co/Qwen/Qwen3-8B#processing-long-texts)。部署前核固定模型与依赖版本；官方最高长度不等于本项目硬件/任务已验长度。

### 3.4 Actor 历史：按实际需要保留事实，不只按轮数切断

近期窗口中的动作、返回和相关观察组成完整事件；不能在一次动作与返回之间切分。较早事件中仍必要的公开事实进入已有记忆能力：对象、字段、值、来源观察/步骤、有效范围与失效条件；区分已见事实、执行结果和未知。事实保留不得使用私有答案或事后独立判定来补 Actor 当时不知道的信息。

例如订单日期、选定商品、已核条件、尚未完成的事项，比保留所有历史页面更有用。对象/页面状态改变后更新或失效；不能仅用同一个临时 DOM ID 证明跨页身份。不能保证必要事实能进入预算时，转长窗口或记录具体缺口，不静默丢弃关键事实。

原始日志/页面继续完整留存；Teacher 仍读取允许的完整尝试证据。当前页任务无需启用记忆，跨页任务按实际消费者接入，不成为全部五站的前置。

### 3.5 自适应观察：紧凑全页与有界局部读取

适用于所有后续新题和经原合同允许继续处理的未完成旧题，包含 Map、Admin、Shopping、GitLab、Reddit。共同入口识别能力、整理并选择模式；不要求每题分区，也不宣称全部结构已实现。按角色、任务合同、观察schema/结构及策略版本验收，未知结构明确支持缺口。Map导航/路线/表格可用相应结构读取；地图画布、图层、bbox、坐标及拖拽仍须保留原合格公开观察和动作绑定，不能仅靠文本裁剪。不得推广仅获特定task资格的Map投影。

已有实际长页面消费者；先核并复用当前自动选择、读取和正文传递能力，只补真实缺口，不从历史未接通状态重建。当前执行顺序为原最小批次先收口（workspace 材料，未发布），再实施上下文改进（workspace 材料，未发布）。按实际依赖接入，已合格消费者可继续推进。

#### 自动选择与全页整理

每轮沿同次捕获取得完整允许的公开观察并保存原引用；先按已验规则做保守结构整理，再组装和计数完整请求。这里的“全页”是本轮完整公开观察，不是全部数据库、未加载分页或任意隐藏DOM。短页面也做轻量整理；无安全收益时可以no-op，不为缩短而丢信息。只能简化无身份/状态/语义的空包装和有精确归属证明的重复表示，保留原ID、值、状态、正文、层级及动作绑定，详见[压缩设计4.2](five-site-context-compression-v1.md#42-actor-视图)。

令 `N_full` 为整理后全页完整请求计数，`H = min(I, C-O-M)`；全页转局部的软阈值为 `S`，须满足 `0<S<=H`。它与局部观察正文的目标/上限分别配置，不要求局部视图填满S。Actor仍为64K/O4096，M=0且配置无更严限制时H=61,440。

<a id="adaptive-observation-settings"></a>

下表仅为**待验收的首版候选配置**，实施时按策略版本冻结，并核实际消费者和任务结构；不是已发布默认值、所有任务适用证明或质量最优值。

| 参数 | 候选值 | 口径 |
|---|---|---|
| 全页转局部软阈值S | 24,576 tokens | 整理后的全页完整请求计数；不是硬拒绝线 |
| 局部观察正文目标 | 约6,000 tokens | 合计概览、目录、焦点区域与读取正文，不要求填满 |
| 局部观察正文常规上限 | 8,000 tokens | 同一激活窗口的合计；仍须核最终完整请求不超H |
| 同一观察连续读取额度 | 最多6次 | 目录、搜索、区域读取均计入，含轻量重复返回 |
| 读取余量提示 | 剩余2次时 | 提示实际余量，不强迫模型转为业务动作 |
| 连续无进展出口 | 连续2次 | 受控退出或原合同允许的处理，不判业务失败 |

| 条件 | 默认动作及例外 |
|---|---|
| `N_full<=S` | 采用保真紧凑全页，避免无必要读取轮次；合法且无收益的no-op写明原因 |
| `S<N_full<=H` | 已支持的局部模式优先；必要完整比较、完整性或接口适用条件要求全页时可保留全页并记录原因，不仅因超软目标拒绝 |
| `N_full>H` | 必须生成合格局部视图并重新核完整请求；无支持接口或必要输入仍放不下则记录具体容量/接口阻断，不删尾、不回退超限整页 |

局部视图的完整请求计数也须不超过H。页面变小时可恢复全页；模式选择只用允许公开事实、结构和冻结策略，不用私有答案或额外模型选区。保留有限候选/切分次数，禁止每轮尝试大量编码或无限缩减。最终计数包括系统、任务、skill、历史、读取/动作工具和模板，不能只计页面或相加片段数冒充完整计数。

显式 `context-projection-policy/3` 的初始候选顺序为 `compact_full_ax → local_ax_navigation → local_ax`：先计完整全页，小页即停止；否则计包含完整公开导航子树的局部候选，合格即停止，仅在其不合格时计有界目录回退。后两者共用 `local_ax` 格式但保留不同候选身份，不能按格式合并回执。实际返回读取仅生成当前激活窗口；不支持局部结构时只生成完整全页，软阈值不否决硬门内的必要全页。旧策略/2保持原候选顺序，不将新选择隐式解释为旧版本。

初始局部视图提供有界全局概览、真实导航/搜索/分页入口、加载/错误/保存状态、当前焦点或最近操作相关区域，另按结构给必要表头、完整行组和祖先关系。目录过大也分页；非交互正文不得普遍丢弃。视口只是可用选择依据，不能把屏幕外内容永久排除；仅设置 `filter_visible_only=True` 不构成读取能力。 文档节点 `RootWebArea` 的 `focused` 只要求保留该节点原行及焦点属性，不能因此将其全部后代列为每次必展正文；完整后代仍由原快照目录和范围入口读取。必要弹窗、实际焦点控件、行身份及上下文继续保护，不能套用文档节点规则裁掉。

首屏质量按“可直接理解和操作”验收：紧凑导航及已展开菜单可在预算内完整展示时，保留其实际链接、状态和必要祖先，不只留容器或焦点的一项，再让模型花一次生成取其余导航。导航本身过大才使用有界目录与继续入口；不得按私有目标或旧成功路线筛选。必要内容保留优先于压缩率，正文较短无需凑目标长度，也不能据此忽略缺失的必要内容。

旧的full-if-fits/实际viewport可作选择策略参考，不回退旧模型窗口或整套运行树。只有同次公开捕获中存在真实可见性元数据才可按视口选择；原AX文本缺该信息时沿已支持的结构规则，不按节点ID/文本位置猜可见性。确有消费缺口才扩展必要捕获产物。整体效果与比较口径统一见[压缩评价](five-site-context-compression-v1.md#context-compression-evaluation)。

“导航1,500、焦点2,000 tokens、前20行”等仅可作为分配目标或辅助限制，不能机械截断。必要弹窗、目录或单行过大时重新分区，保留必要上下文并给继续入口；仍不能满足容量/完整性合同则明确超限。行数不能替代token预算，局部观察预算也不能替代完整请求硬门。

#### 同快照范围读取合同

通用读取按公开结构组织：AX子树、表格行组、文档章节、代码区间、评论子树、空间结果列表；站点仅提供必要适配器。优先使用网站已有搜索/分页/筛选/展开解决实际业务读取，但这些是原网站动作，不能由压缩器暗中执行；同快照材料读取不调用网站step或重新捕获初始观察。数据库分块不等于Actor已有该能力。

| 读取职责（实际名称/版本以所选入口为准） | 输入 | 输出和必要约束 |
|---|---|---|
| `list_regions` | 已允许snapshot、分页游标、输出预算 | 有界区域目录、公开标题/类型、是否仍有目录及继续入口 |
| `read_region` | 同snapshot、region_id、范围/游标、输出预算；可显式携带有限多个范围 | 原ID、正文、必要祖先/表头、逐范围完整性、下一游标；多个范围共享一次输出预算 |
| `search_regions` | 同snapshot、公开查询、预算 | 带上下文的可追溯命中、搜索覆盖与剩余范围；未命中不等于整个网站不存在目标 |

共享DTO至少包含 `snapshot_ref, observation_version, scope, region_id, source_span, content_type, content_ref, required_context_refs, complete, continuation, omissions`，绑定task/attempt、tab/frame及冻结策略。`complete`明确针对请求范围。游标不跨快照/任务使用；不可接受任意文件路径、后台数据或私有引用。未加载/未展开/未覆盖、加载错误与真实空结果分别表示，虚拟列表或下一网站分页须通过原允许动作取得新观察。

优先按完整结构切分；单元格/代码段自身超预算时按明确源范围继续，保留必要上下文，不能拆坏Unicode、动作参数、列归属或否定条件。原始全量允许证据保留；全页压缩证明内容/关系保留，局部投影另证所选内容真实、范围完整且剩余内容可定位读取，不能关闭原保护器或冒用旧full-AX版本标签。

首版搜索固定为当前允许快照内、不区分大小写的字面子串匹配：源文本和查询使用相同Unicode `casefold` 规则，冻结实现/Unicode版本；不额外做空白、重音或兼容字符归一，不默认支持正则、模糊或语义搜索。归一后的匹配位置须映回原正文范围，不能直接用归一索引裁原文。多关键词仅在单独声明并验收后启用，显式选择 `all` 或 `any`；空查询/错类型受控拒绝。

表格命中携带行身份、表头映射及完整行上下文；超长行明确未完整返回和继续入口，不静默截断。代码保留path/ref、源行号和原缩进，评论保留对象及父子关系等各自必要上下文，不能统一套表格规则。返回搜索覆盖范围、覆盖是否完成、结果是否耗尽和继续入口，区分扫描未完、结果分页未完与已覆盖无命中；当前快照无命中不等于整个网站没有目标。

#### 读取循环、预算与生命周期

Actor须能选择“读取更多”并真正消费返回后再生成；未注册工具不写入提示词。读提案、读返回、实际进入模型的范围及业务动作分别记录，读取不冒充网站动作，新增模型调用仍计入原生成次数、token、费用和任务期限。读取次数、返回容量、准备时间及无进展退出有界；不额外扩大原授权预算。

提示词从开头到结尾使用同一输出合同：有已注册读取能力时，恰好返回thought加一个action或一个read；没有读取能力时仅声明动作。按实际schema构造完整合法示例并用真实解析器验证，区分浏览器函数字符串与读取对象，不在“只许action”的旧协议后追加相冲突说明。未执行的解析拒绝单独列为提案反馈，明确未执行、错误字段及合法格式；不放在已执行业务动作/读取结果下，也不把拒绝解释为搜索无命中。保持严格解析，不猜意图、不自动补发、不改写旧拒绝。

区域数量的提示、校验和拒绝反馈共用当前原始输入绑定的冻结 `max_ranges`；先核有效上限，再核schema绝对上限，拒绝须说明实际数量、有效上限、未执行及未知区域先用 `list_regions`。解析前拒绝也按原持久拒绝事件单独核连续重复提案：身份包含完整公开快照/scope、冻结策略、结束状态与全部操作参数，忽略thought和JSON键序；只改变请求ID不重置。阈值采用同一冻结策略的 `consecutive_no_progress`，独立于已执行读取的 `no_progress` 计数；相同身份连续达到阈值即受控错误停止，不再生成，不记读取或业务成功，外层仍恢复关闭。合法动作/读取或快照/策略/参数改变结束该重复序列；旧未声明读取策略的action-only输入不推断新阈值。原返回、拒绝、费用及unknown保持，不用新规则改写历史结果。

现代 `actor-run-request/2` 的公开动作历史以 `actor-history-item/2` 显式携带 `executed`，按实际trace的动作/拒绝事件构造；读取仍走原独立事件，不伪装动作。旧未标记历史保持原wire且执行状态未知，不从动作或错误字符串猜测；新提示分别呈现已执行动作、未执行提案及旧未知记录。示例绑定当前允许动作与真实注册工具/公开快照，页面文本不产生额外能力或执行事实。

首版采用**一个激活阅读窗口＋结构化读取记录**，不同时引入K=2/FIFO。新读取成功核验后替换窗口正文；失败不把未返回材料写成当前窗口。跨区域比较由一次显式读取携带有限多个范围，合计受同一局部正文和完整请求预算约束。移出窗口的正文仍可按原快照重新读取；如比较所需事实尚未可靠保留，须合并读取相关范围或使用已验事实记忆，不能只留“读过了”的标记。

读取记录至少保留 `region, range, snapshot, delivery, content_ref`；`delivery=returned` 表示工程返回成功，`delivery=included_in_model_input` 另须绑定确实纳入的模型输入引用及范围。二者均不表示模型已经理解或核查，禁止记录为“状态=已核查”。原事件保留，窗口正文不逐轮永久叠加进提示词。

字段示意如下，沿原context/trace保存，不新增wire schema：

```ini
region=products
range=rows:1..50
snapshot=<原快照引用>
delivery=returned
content_ref=<本次返回正文引用>
```

后续确认该范围实际纳入模型输入时，关联同一次读取另记`included_in_model_input`及对应输入引用/范围，保留原返回事实；仅返回、未确认送达时仍记为`returned`，不能先行标为已送达。

按同一观察和原scope计连续读取额度，目录/搜索/区域请求共用；显式多范围读取算一次请求，各范围不能各领一份预算。重复身份同时包含快照、范围、游标、查询/匹配模式和其他读取选项，不能仅按工具名或region判断。请求当前窗口已展示的同一内容可轻量返回，计读取次数和无进展；请求已移出窗口的内容若合法重新送入则允许，不因历史读过就拦截。进展按真实新增或恢复的展示内容、经核实的目录/搜索覆盖推进等工程事实判定；仅更换请求ID、游标表示或读取选项不构成进展，不凭返回成功或模型“已核查”推断。

达到额度或连续无进展条件时，禁止新增读取，保存实际余量/重复身份/覆盖及停止原因，走受控退出或原合同允许的处理；不能强迫点击、猜答案，也不能把信息不足出口当成有效业务失败。额度内最后一次合法读取的返回仍须保存并如实记录送达状态；原合同与剩余总预算允许时可供下一轮使用，不因额度恰好用尽而丢弃，也不因此额外授予一次模型生成。相同观察不因换请求ID或重新组装输入重置额度；新观察仍受原生成/任务/作业总预算约束。候选数值按上表验证后才能成为具体消费者配置。

同快照已验正文、结构索引及完全相同的只读结果可在明确有效生命周期中传递，不逐层远程重读；动态权限/claim/撤权和资源账本仍核。新观察或原scope失效时更新/清除旧当前视图；旧材料只作历史，动作前核当前版本、目标与tab/frame，不能按同名猜测替换对象。每次读结果有界组装，不把所有展开片段永久叠入上下文；必要早期事实按3.4处理，不能静默删事件。

整理、计数和保存使用有界准备窗口；生成仍在最终准入和真实派发边界取得原选定执行窗口；读取及返回/保存计入阶段、任务与作业总期限，保留收尾余量。所有失败按原请求/恢复合同保留首错与清理错，已发送/unknown不换视图重发。原已存返回优先合法补核/补登记。

Generator只获既定允许的任务/初态内容及实际能力声明；Teacher保留完整允许事件，区分Actor实际已读、未读和事后材料。不得只以局部视图替代Teacher原证据，也不新增分块Teacher调用。

最小泛化检查覆盖Admin长表、Map实际受影响关系及另一种结构（代码/评论等），使用保留的合法公开材料与必要夹具；核末区目标、同名对象、超长目录/单格、表头、代码顺序、评论父子、错快照、重复/无进展、撤权、取消和部分保存/收尾失败。按真实生产构造器验证读取到下一轮输入及发送/封闭消费者，证明复用正文未再次执行昂贵读取。软件/安装通过后随原合法业务批次收模型行为与整题成本，不重放有效失败，不新增全站预跑。

### 3.6 分层skill与读取能力一致：先取证，再定位和执行

动机与因果边界：此次MapData未启用通用分区读取。用户对原轨迹的复核指出，实际输入保留`[468] Layers`，Actor却选择其他对象；这属于需要分析的目标到动作对象映射问题，不能当作压缩删除控件或分块造成失败的证据。原有效失败保留，不为检验本设计重放原题。分层指导有助于明确操作条件，但不能保证模型遵守或必然成功。

**三层职责，共用一套实际能力合同：**

1. Actor公共协议说明如何使用当前真正可调用的观察/读取/动作接口，以及快照、ID、范围完整性、错误处理和预算。通用规则只写一份，不重复塞进所有skill。全页模式不要求先读分块目录；分区工具未注册时不得提示模型调用拟议工具名。
2. Generator和Teacher产出的skill说明任务的阶段目标、需要观察的证据、对象定位条件、动作和完成检查；必要时包含条件分支。skill指导如何找到当前对象，不固定原轨迹的ID、region_id、游标或坐标，也不声称未知的后续页面一定具有某个控件。
3. 每一步由Actor依据实际返回执行：确认可见证据与当前对象→调用允许动作→读取结果→判断继续、重新定位或停止。执行器核已声明的工具/ID/快照/权限；不能凭一段thought推断真实意图并替模型自动改成另一个点击，也不能把合法ID检查等同语义目标正确。

**现有格式边界：**当前`domain/skill.py`的CompactSkill只有`title/principle/when_to_apply`三个字符串；`domain/skill_limits.py`限制principle最多6个连续编号步骤、200英文词，三字段共220词，并拒绝项目符号过程。`generator/instructions.py`已要求role/label/scope、当前ID和完成条件，不能重复宣称这些要求是本次新能力。首版在原principle内用连续主步骤、步骤内条件句表达层级：阶段目标→定位证据→操作→检查/失败分支。避免嵌套数字编号与现有解析冲突，生成仍遵守原英文JSON合同。不增加第二个planner、不改top-6/四候选；确有证据表明现合同无法承载时才单独提出版本变更，并同步Generator、Teacher、Actor、检索库、导出和SFT消费者，不能私加steps字段。

**Map的示意指导（说明结构，不是已验skill或执行脚本）：**

1. 定位图层入口：检查当前观察中的Layers及其控件角色/所属地图工具区域。仅当该信息不在已读范围且确有分区接口时，先查目录/公开标签，再读取该区域及必要父级。目标已明确时直接定位，不额外强制读目录。
2. 打开入口：使用当前观察中对应控件的ID；比例尺、空链接、Marker不能因邻近而替代Layers。多个同名目标时先补读上下文，页面版本改变后重新定位。
3. 验证打开：检查返回是否出现所需图层面板/选项；点击无报错不等于面板已打开。未出现时根据实际反馈重新定位，避免无新证据反复点击无关对象。
4. 完成目标：按任务要求选择实际存在的数据选项，检查Actor可观察的选中/加载/地图显示结果。未加载、报错或范围未读完时不得宣称成功；私有数据库判定不作为Actor可调用步骤。

同一结构适用于Shopping的目标商品行、GitLab项目/文件、Reddit评论父子关系、Admin记录编辑；每个skill保留该任务确需的定位及完成条件，不附所有网站的通用故障清单。

**Teacher和Generator对齐：**

- Generator仅使用原允许的任务、初态和检索skill，并获知当前Actor实际支持的观察模式/工具合同；不能从Teacher完整轨迹或私有判定引入未来事实。初态未知的细节写成观测条件，不写成已知状态。
- 所选能力由[构建配置绑定合同](codebase-architecture-v1.md#construction-selected-actor-capabilities)贯通：plan4私有配置引用→input2公开能力→原factory/首次Actor请求→独立复核与v7导出。工具仅按当前允许快照实际注册；不能全局置为可读、向Generator暴露私有配置/claim/计数引用，或把旧plan3/input1/v6静默改写为新版。公开初态和检索合同不因该能力声明扩展。
- Teacher保留允许的完整轨迹，同时区分“当步确实送达Actor的输入”“之后的观察/判定”和“未送达/未知”。复用现有`teacher/instructions.py`的Actor-visible约束；完整页存在不代表Actor读过该区域。
- 接入分区的实际消费者，其原轨迹/Teacher材料必须记录读取请求、区域/游标/快照、实际返回范围、完整性、错误及是否进入Actor输入。Teacher看到Actor未读的必要公开信息时，应修订为“先读取该区域并确认”，而非让Actor直接使用事后得知的值。只读材料查询与网站业务动作分别标明，遵守同一总时限及有界读取预算，不绕过原一次派发/错误合同。 含显式观察视图或读取事件的原生尝试使用 `teacher-original-actor-attempt/2`：保留完整允许AX、准确Actor输入和独立只读返回；`actor_observation_view`给出实际范围，`observation_read.delivery_records`只从原完成返回及对应输入确认送达。空送达记录表示未确认，不能推断从未送达；返回和送达均不表示模型已理解或核查。公开投影不携带私有StateScope、计数/存储引用或诊断正文；原版本1字节与消费者保持其原合同。关闭后正式构造器须显式装配同一来源核验器，独立复核不调用前向Teacher组合器，不重新计数或调用模型。
- skill的适用性绑定现行执行上下文中的能力合同版本；检索出的skill若需要不存在的工具，应走现有适配/拒绝出口，不能直接发送给Actor。新增字段如不可避免须显式升级所有消费者，不能仅写提示词后声称接线完成。

**实施与最小验收：**先复用现有scope/允许动作/可见证据，完善原Generator/Teacher提示和对应受影响格式检查；分区专有接线只在真实启用分区的任务上实施。纯合同检查覆盖未注册工具、全页无需读取、目标在未读末区、同名对象、旧ID/旧快照、空/部分返回、重复读取/无进展、取消/预算耗尽、点击后未展开、Teacher误用事后信息，以及skill三字段/字数/编号和旧消费者兼容。Map已知“目标文字正确而ID错误”的材料作为回归案例，不硬编码468为正确答案；增加至少一种异站结构案例验证规则并非Map专用。模型是否正确选目标及修订skill是否有效随原合格任务批次观察，不新增压缩专属全站预跑，不以格式测试通过证明行为改进。

## 4. 三个角色分别承担什么

| 角色 | 必须提供 | 优先优化 | 不能做 |
|---|---|---|---|
| Actor | 任务/约束、当前有效观察、动作协议、适用 skill、近期反馈及必要早期事实 | 保守格式、实际需要的事实记忆、长窗口；必要时分区观察 | 丢操作 ID/目标关系、裁掉早期关键事实、把错误页当正常业务页 |
| Skill Generator | 原方法要求的任务、初态与 top-6 检索 skill 等既定输入 | 独立预算、模板整理、保留各 skill 身份的精确重复内容处理；本轮不扩窗口 | 无依据改 top-6/四候选方法；添加完整 Teacher 私有轨迹；默认裁减候选数 |
| Teacher | 允许的完整候选/修订尝试、动作与返回、错误、终态和反馈 | 正文单跳共享、明确事件关联、独立服务窗口与费用约束 | 只保留最近 N 轮、删失败尝试、将动作提议当执行、用 Actor 派生页替代全部允许原证据 |

Teacher 窗口更大也需要硬门。压缩收益不等于理解收益；优先保留事件附近的简短因果标记，避免因省少量 token 让模型跨候选反复查找。输出仍走原 Actor 复验、独立判定、选择/导出，不新增一个仅凭 AI 自评分就放行的环节。

## 5. 模块和接口边界

以下为逻辑职责；复用当前已有文件与类型，开工先核实际源码。候选新名字不要求一律新建文件或平行接口。独立职责分 Python 文件，不把角色输入、计数、策略、模型加载和网站读取合进一个控制脚本。

| 位置 | 职责 |
|---|---|
| `domain/context_budget.py` | 复用预算/测量合同；必要时补显式运行档位与容量阻断原因 |
| `policies/context_budget.py` | 纯预算判定、有限档位选择，不访问模型、网站或费用服务 |
| `actor/context_projection.py`、`teacher/context_projection.py` | 角色表示整理，保留各自保护/审计职责 |
| `generator/prompting.py` 及对应适配层 | 保持既定生成方法，接入同一预算依据；不直接调用 Actor 投影 |
| `adapters/models/context_tokens.py` | 完整消息计数及兼容缓存；不创建运行授权或派发请求 |
| 现有 Actor engine 配置和 `causal_transformers.py` | 受控加载 Actor 已验证长窗口、原模型会话与资源释放；共享改动保持 Generator 原配置行为 |
| `application/context_preparation.py` 与角色调用方 | 发送前编排、选择原权限内档位、持久化、交原请求账本 |
| 现有记忆模块／独立事实投影文件 | 事实提取、更新、失效和来源；不生成隐藏知识或新 Judge |
| 现有 observation 端口及网站适配层 | 按3.5接通实际消费者的范围读取、版本绑定与能力声明；公共遍历规则复用，站点提供结构差异 |
| `bootstrap/` | 冻结配置装配；统一现行消费者，不靠漏参数回退旧接口 |

拟议纯策略结果可表达为 `ready(profile_ref, input_ref, measurement_ref)`、`needs_supported_view(reason)` 或 `blocked(reason, evidence_refs)`，具体复用现有状态枚举，不另造状态账本。领域/端口不依赖网站实现；应用只依赖端口；bootstrap 负责注入。

每份计数绑定完整输入摘要、角色、模型/tokenizer/template、计数器版本与计量选项；profile/预算改变需重新判定准入。内容计数缓存命中不等于权限、费用或来源许可可复用。最终计数/分词结果能否复用给生成，由原 worker 身份及输入一致性决定，不新建全局缓存服务。

## 6. 状态、异常与不重复请求

建议在既有准备状态中表达：`来源核验 → 表示/计数 → 有限档位选择 → 保存准备回执 → 原一次派发`。超限只发生在派发前；已经发出的请求沿原账本处理。

| 情况 | 处理与证据 |
|---|---|
| standard 超限、合格 long 可容纳 | 派发前选择 long，保存所选配置及计数；不先发送 standard 试错 |
| 没有合格档位/资源或必需信息仍太长 | 保存完整材料、具体缺口和下一处理项，状态为容量/资源阻断，不判业务失败 |
| tokenizer/template/profile 不匹配 | 配置错误，拒绝；不自动换模型或静默截断 |
| 长窗口加载失败、OOM、超时 | 保存首错与清理结果，按原资源/请求合同结束；不自动切小窗口重发 |
| 分区页面版本过期 | 拒绝旧目标使用，按原观察流程更新；不把旧范围当当前事实 |
| 输出到长度上限/JSON 不完整 | 保留原响应，按既定修订/错误规则处理，不当成功，不自动续发 |
| 派发后结果未知 | 原 unknown 保持，不靠换 profile、attempt 或 request ID 重发 |

容量处理失败有明确出口，并不等于永久放弃。后续在合格配置、资源和原执行规则满足后接续；这不提供重放历史 unknown 的许可。两来源并行、写状态隔离、原总费用和付费并发 1 保持。

## 7. 开发顺序、工作量和验收出口

| 阶段 | 范围/相对工作量 | 完成条件 |
|---|---|---|
| A：预算盘点与诊断 | 小；先复用已有完整输入/配置/回执 | 分清角色和超限来源，计数口径完整；有具体消费者，不按全题池重测 |
| B：保守格式优化 | 小到中；空名称/重复叶子等逐项有收益才实现 | 所有必要字段/ID/层级与绑定通过；完整消息实测有收益；未变缩进证据复用 |
| C：Actor 长窗口档位 | 中；配置/加载/资源/计数/准入接线 | 模块边界通过、实际目标长度加载与推理资源检查通过，保存新冻结配置；真实任务效果随批验证 |
| D：独立预算核对 | 小到中；可与 C 无依赖部分并行 | Generator 保持现行配置且不套 Actor 上限；Teacher 真实路由/计量/费用通过才发；不新增 Generator 扩容 |
| E：Actor 跨页事实记忆 | 中；仅具体任务需要时 | 已有公开事实正确提取、更新/失效、来源及输入/复核一致；无需每站都先实现 |
| F：范围读取 | 较大；仅容量/任务证据证明需要时 | 页面范围/身份/覆盖/版本/动作语义及真实消费者通过；未支持项明确阻断 |

上述是职责范围，不是每次重新执行A到F的串行计划。当前自适应观察增量按交接文档（workspace 材料，未发布）核已有A/C/D及共同修复证据，只补B/F与实际受影响消费者；E仅在必要历史确有缺口时接入。Admin长页和受影响Map入口的读取缺口须在其依赖提交前解除；不把全部五站E/F覆盖作为无依赖合格任务或训练链的新全局门。

测试按模块变化选范围：正常/空/非法类型、hard−1/hard/hard+1、输入+输出+开销边界、无可用档位、错版本/缓存、重复调用、取消/部分保存失败、OOM/关闭、unknown 禁重发。记忆补过期/冲突/来源混淆；范围读取补目标在尾部、同名对象、表头跨范围和页面更新。

先检查新夹具，失败保留完整报错与复现条件，解释根因后最小修复，先失败节点再实际受影响回归。相同冻结版本共享静态/只读安装准备；无关已过证据复用。真实模型配置变化需要相称的真实验证，不等于每个小改都重跑五站。原项目最终整体门按原阶段执行一次，不新增长输入专属全回归。

## 8. 交付及当前明确不变的事项

每阶段交付：实际消费者与最小改动、精确配置/源码摘要、已执行及复用测试、完整输入/计数/处理选择、资源/时延成本、运行结果与未知范围。五站覆盖按任务族/角色登记，不因共用模块存在宣称全部题目可运行。

A40 64K已有上述限定范围的验收；记忆和范围读取按实际消费者复用原包实现、安装及运行证据，未覆盖范围明确列出。原三任务、top-6/四候选/既定修订方法、五站初步验收与训练范围组合、独立导出、小 SFT、完整框架/test-dev/RL 目标保持。正式流程发布时统一当前入口、发送和独立复核接口；历史证据隔离读取，不为兼容历史继续产生旧格式。

优先判断成功标准：Actor 有足够信息定位并验证操作，Teacher 有正确因果依据修订 skill，Generator 的输入与训练方法一致。token 减少与通过检查数只是工程指标，不能代替这些目标。
