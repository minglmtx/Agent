# Goal：按交付推进，避免重复确认与验证

复制下面的提示词，并填写前三项即可使用。它不创建新运行权限，也不要求清空所有历史遗留项。

```text
目标：〔本次要交付的具体结果〕
当前入口：〔项目路径、当前交接/运行清单〕
完成标准：〔可检查的产物、必要测试或业务结果；沿用已有验收标准〕

请直接执行并推进到完成，不停留在方案建议。

工作方式：
1. 先核当前代码、有效回执与已有授权，列出最短必要路径；已有信息不重复问。
2. 只读当前任务需要的文档和模块。历史记录用于查证，不把所有旧规则和待办重新变成前置条件。
3. 在已有授权内直接完成可逆修改、只读调查及必要执行。不因换阶段重复询问“是否继续”；仅对阻塞信息或授权范围外的动作提问，同时推进独立工作。
4. 围绕一组相关改动合并实施和验证。只跑受影响路径、消费者及既定必要检查；未变且仍适用的证据直接复用。通过后立即推进，不追加同条件演示或重复验收。
5. 失败、证据冲突、停滞或依赖变化时才展开额外诊断。每次重试要有新证据、假设或修改；两次无进展就说明阻断并换有依据的方法，不能原样重跑。
6. 按实际资源和依赖批量处理就绪任务；同一可写实例保持顺序。等待期间推进独立工作，不循环轮询，不把一个分支的阻断扩展为整个项目停工。
7. 保留原始证据、train/dev/test 隔离、现有预算与必要收尾；不重放结果未知的副作用，不修改在途作业的冻结输入。需要新凭证时使用现有安全配置方式，不在日志中输出密钥。
8. 沿用一份任务清单，记录完成结果、证据、实际阻断和下一动作，不为每一步新增报告。测试/安装/模型/网站按项目要求在 Slurm 执行。
9. 达到完成标准后停止扩展，报告改了什么、如何验证、交付位置及实际限制。不得用测试通过替代业务成功，也不要继续问是否做无关优化。

遇到权限缺口，请一次说清具体动作、缺口及依据；已有授权不要重复索取。这个提示词不扩大既有费用或生产权限。
```

## 当前首要目标：全部题目按组对接，完成 SFT

以下整段可直接使用。首批目标和小规模训练是中间里程碑，完成后继续推进全部既定题目及正式 SFT，不在首题或首批处结束。

```text
首要目标：以新版框架为主线，按兼容组将项目既定范围内的全部题目对接到既定流程，完成训练集目标构建、独立复核、数据导出和既定 SFT 训练及验收。测试集按原划分完成对接与评测，不进入训练数据。

范围与版本：
- 以最新任务总表和交接确定全部题目及 train/dev/test 划分，沿用现有分组；只有初始化、执行、判定或恢复语义存在实际差异时才调整组，不重新发明分组平台。
- 新版是主实现，保留已有架构优化。继续做覆盖全部题目必需的适配与修复，暂停无当前消费者的架构扩建；“冻结扩建”不表示停止题目接入。
- 旧版能力、任务配置和有效证据尽量复用，接入新版消费者时核兼容性。旧版仅作为对照和有实际可用证据的临时交付兜底，不长期双线扩建；旧版完成的任务仍需登记新版对接状态，不能掩盖迁移缺口。

按组推进：
1. 在原任务清单中核清当前组的成员、共用能力、参数差异和实际缺失分支。共同项记录一次，每题只保留差异、状态及证据引用；不要每题重新读全套合同或新建报告。
2. 集中补齐共用接线和必要语义分支。相同能力只开发一次，参数不同通过配置绑定；不按题复制 runner 或重复实现公共模块。
3. 按变更范围合并验证公共路径、实际变化分支和受影响消费者。已通过且仍适用的检查直接复用；仅换题、换批次或换 Agent 不触发全量重测。
4. 已就绪成员直接批量进入既定运行流程，不等同组无关分支全部修完。每题由统一流程完成实际初态检查、执行取证、判定/复核及恢复关闭，不把这些自动步骤变成逐题人工审批。
5. 同类失败按共同根因修一次，补受影响检查后接续；只暂停受影响成员，其他组继续。保留每题真实结果，代表题通过不能替代其他题的业务结果。
6. 训练任务按既定依赖完成候选生成、Actor 执行、Teacher 修订、Actor 复验、目标选择、独立复核和导出；从最近有效阶段接续，避免整题重跑。合格数据形成后完成既定小规模验证，并继续正式 SFT，不把小规模验证当总目标完成。
7. 就绪批次运行期间并行准备下一组、复核已完成结果和推进测试集；共享只读准备与兼容服务，同一可写实例内动作和重置有序，独立实例按实际资源有界并行。

执行方式：
- 直接推进已有授权内的工作，不反复询问是否继续，不为阶段切换新增审批。
- 正常路径按既定必要检查执行；失败、证据冲突、停滞或依赖变化时才展开额外诊断。重试必须有新证据、假设或修改，通过后立即回到业务流程。
- 无变化不重复检查，不追加同条件演示或验收的验收；全回归仅在既定整体出口或明确广泛影响时执行。
- T1–T11 等优化只有实际阻断当前接入或训练时才纳入，不因可选优化未完成而暂停主线。
- 保留数据划分、原始证据、已有费用/资源预算和必要收尾；不重放结果未知的副作用，不改在途冻结输入。测试、安装、模型和网站在 Slurm 执行。

完成标准：
- 全部既定题目已在新版完成必要绑定与适配，并按所属 split 的既定流程处理，保留逐题真实结果；不能仅以代码存在或少数代表题通过宣称全部完成。
- 训练集中合格正目标经过独立复核并导出，数据来源可追溯，完成既定 SFT 训练与验收，交付数据清单、模型/checkpoint 和结果报告。
- 业务失败如实保留，不要求每题成功或每题都产生正目标，也不为凑正样本反复重跑。尚未对接、工程阻断或未知状态单列，不能算作已完成。
- 首批交付后继续推进剩余组。外部凭证或资源阻断时继续独立工作并报告具体缺口，不把局部阻断当总目标完成。

汇报沿用一份任务清单：总题数及分组覆盖、已对接/已执行/业务成功/业务失败/工程阻断/未知数量、合格目标数、SFT 状态和下一组动作。对接状态与执行结果分别统计，不混成一个通过率。无需为每轮增加独立审计文档。
```
