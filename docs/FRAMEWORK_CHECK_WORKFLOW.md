## 日常执行入口（2026-11-11）

当前首要目标是**全部既定题目按兼容组接入新版，并完成目标构建与 SFT**。首批交付只是里程碑；继续推进剩余组。共用能力集中适配和验证，每题只补参数/语义差异及实际运行证据；已就绪成员不等无关分支。详细 goal 以 [当前目标](GOAL-PROMPT.zh-CN.md) 为准。

**默认直接推进已授权任务；下文细则按当前问题查阅，不是每轮必须遍历的检查单。** 本节统一日常执行节奏；后文历史流程中的“核对”指检查实际变化和适用范围，不要求重新执行全部检查或另开审批阶段。运行时必要的权限、数据隔离、预算、未知副作用和收尾约束继续适用。

1. **开工一次定出口。** 从当前 goal 与交接确定交付物、必要检查和已有授权；沿用原清单。已有明确标准不重新设计一套验收。
2. **按需读。** 先看当前入口、受影响模块及最近有效回执；只有遇到具体依赖或冲突再打开相关合同。历史日志用于查证，不作为新增指令。
3. **正常路径直接做。** 可逆代码/文档修改、只读调查和已授权范围内的执行不反复问“是否继续”。缺权限只阻断该动作，不阻断独立工作。
4. **按事件扩展诊断。** 工具失败、结果冲突、实质停滞、依赖变化时定位原因。阶段切换仅核新阶段需要的输入与现场事实，不全量复审前序。日常必要测试照常执行，不等出错才验证。
5. **验证随改动合并。** 改完一组关联内容后跑受影响检查；失败先修并重跑失败节点。无新增变化或证据缺口，不再跑刚通过的检查。文档只查格式和引用；全回归按既定交付要求或明确的广泛影响执行。
6. **诊断要有出口。** 同一失败连续两次诊断仍没有新证据、修改或进展，就记录具体阻断，换有依据的方法或推进独立任务。两次是停滞提示，不是忽略失败、自动重试副作用或强行标记完成的理由。
7. **通过就推进。** 输入、必要检查和既有执行资格满足后，直接进入下一已授权阶段，不增加同条件演示、验收的验收或无关优化。
8. **只维护一份状态。** 复用原包清单和不可变回执，汇报交付结果、必要验证、具体阻断与下一步。不要把日志条数、测试数量或新文档数量当作业务进展。

需要询问时，明确指出缺少的具体信息/授权及其来源。用户已有授权仍有效；不能仅因任务跨阶段或换会话再次索要。发布、付费及破坏性操作是否需要确认取决于已有授权范围，不能一概重复确认。

## 2026-11-03现行补充：调度替代与blocked判定

2026-11-04复核修订。PENDING先判断原因和实际可用候选，再决定调整或保留队列；RUNNING、实际Actor执行、完整闭环分别汇报。等待时间不计为业务运行时间。下列规则在既有授权和资源预算内执行，不新增审批或独立交付阶段。

### 观察时限与触发动作

- **提交后首次观察**：核JobId、实际控制器字段、依赖和冻结输入，记录状态及下一次复查时点。agent活跃推进期间，PENDING默认每5分钟复查一次；原因首次出现或变化、依赖终态、资格检查完成时当轮诊断，不等下一固定周期或用户提醒。
- **稳定容量等待**：已核完兼容替代、没有可行调整时，可改为每15分钟复查；记录候选容量依据及下一动作。单次阻塞等待不超过60秒，间隔用于独立工作。该节奏是agent执行规则，未安装后台监控或通知服务，结束会话不能声称仍在自动监控。
- **运行状态**：核实际阶段、最近进展和原operation期限；超过该阶段已记录的预期耗时或进展更新时间，读原日志/资源与调用链定位。缺分段数据明确登记，不能只凭RUNNING反复等到总时限，也不能据静默自动重提或扩大deadline。
- **终态及时收件**：每次调度诊断同时检查本包依赖、资格和安装作业。完成的检查当轮核退出码、result、原输入稳定性、清理/关闭及适用范围；更新原包摘要。Slurm COMPLETED不直接授予业务资格，但旧PENDING也不能继续作为冻结或等待理由。

### 原因与处理出口

| 当前事实 | 当轮动作 | 允许继续等待的条件 |
|---|---|---|
| ReqNodeNotAvail / UnavailableNodes，DOWN、DRAIN、DRAINING、维护 | 同时读scontrol show job、节点/分区状态及实际请求；计算兼容候选。候选受到可修配置限制时，在原授权范围落实调整并回读 | 已说明为何无可用替代、保留有效队列，并安排独立工作/下次复查 |
| Resources / Priority | 核CPU、内存、GPU、型号资格、保留与账号/QOS限制；这些也是正常排队原因，不能把改Reason当优化目标 | 请求正确且容量/优先级等待有证据；不通过反复取消重提抢占优先级 |
| Dependency / DependencyNeverSatisfied | 核父作业实际终态；成功父回执已验后核依赖释放。失败父须最小修复，保留原失败及未启动子作业，再按原规则建立唯一后继 | 父仍在合法推进；不可满足依赖不能无限等待 |
| JobHeldUser / 配置或提交失败 | 核是否为本项目有意hold以及释放前置；已满足即执行原释放流程，未满足写具体缺口 | 仍有明确未满足前置，不能把本地hold误称集群拥堵 |
| RUNNING后故障或状态未知 | 按原owner核实际step、会话、claim、资源和收尾，不适用“未启动换队列”处理 | 合法诊断/收尾仍在原期限内，未确认状态继续隔离 |

**UnavailableNodes不是节点绑定。** 节点约束以ReqNodeList、ExcNodeList、Features、分区及控制器实际资源字段为准。Reason可能在节点已排除后仍显示该节点；它本身不能证明作业被绑在那里，也不能证明排除规则失效。先核实际候选和调度器最近评估；原因不一致仍不能解释时保留原查询证据，记录需集群支持核实的具体字段，未经用户指令不代发外部消息。

**可用候选必须综合判断。** 在分区和必要Features/GRES范围内应用节点约束，再核已验硬件/驱动/安装、CPU/内存/GPU、时限、保留、账号/QOS及可接收新作业状态。DRAINING可能显示drng并带@/*等标记；剩余数字不等于允许新分配。ALLOCATED也要看剩余资源，不一律当故障或可用。本项目真实GPU消费者和纯软件检查分别判断；纯软件可用兼容CPU/其它已授权分区，不移到登录节点。

### 有效调整、冻结与唯一后继

1. 操作前再次确认原作业仍PENDING。优先原地保留JobId和依赖，移除无必要硬绑定、合并明确适用的故障排除或扩展已获资格的分区；已被排除/不属于候选的故障节点不重复修改，不为清掉Reason排除整个维护集群。不修改节点状态、账号权限或优先级，不扩大原预算。
2. 回读Partition、ReqTRES、TresPerNode、Features、ReqNodeList、ExcNodeList、Dependency及MinMemoryNode/MinMemoryTRES、MemPerTres和CPU比例。脚本与提交命令不是最终控制器事实；总内存与每GPU隐式请求都要一致。动作后仍排队如实记录，不能用Reason变化或预计StartTime表示已经运行。
3. 调度兼容须与不可变生产配置一致。核原模型/运行时/硬件实测回执、GPU类、部署、入口选择和实际物理身份。一个分区内有40GB/80GB等多型号时，不能只按Partition选配置；须具备各型号已验部署并按实际分配选择且在副作用前核对，或用适当Feature严格限制已支持型号。硬件检查通过不等于生产接线已经完成，也不改变Actor64K/O4096或当前任务来源/claim门。
4. 已提交但未启动的作业也冻结实际读取的源码、入口和外部pin。等待时可在隔离候选补适配，不能热改待启动输入。已完成检查自身的冻结理由及时解除；若还有其它待运行/运行消费者引用同一文件，继续保留相应冻结。
5. 必须更换不可变安装或无法原地修改提交参数时，先保全脚本/参数/部署/原回执，核sacct历史、Restarts/step和项目source/session/claim等副作用事实；PENDING且RunTime=0单独不能证明从未执行。核实后按原授权结束旧未启动提交，确认终态再提交唯一后继并更新依赖。竞态中已启动则立即转原运行收尾规则；unknown和已消耗尝试不能借换队列重发。

### 等待期间的交付与记录

每次进入等待前，在**原包清单/汇总**记录：observed_at（含时区）、JobId/状态/原因、实际请求与冻结范围、已核候选/容量、已采取动作及回读结果、剩余具体阻断、wait_since/next_check_at、waiting_work（具体下一组/文件/消费者及产物）。记录字段可沿用等价结构，不新建调度平台、审批或权威账本。

等待期间优先收已完成回执与解除过时依赖；再推进下一完整组的静态绑定、隔离候选必要代码/测试准备、原unknown只读核对及训练必要材料。只完成这些工作的相应授权范围，不新增费用、运行资格或共用可写状态。若任务已无可推进事项，应说明逐项依赖和下一出口，不能仅循环sleep/squeue。连续三轮同阻断只是整体goal blocked的必要条件；还须核兼容替代并确认没有有意义的独立工作，不能把局部资源等待等同整个目标停止。

### 通用准则：省略不必要和重复操作

默认省略没有当前消费者、实际变化或证据缺口，且不属于原必需门的操作；适用于开发、检查、安装、来源、模型、复核、训练及文档。按[最小检查范围](#change-evidence-scope)选择本轮动作，共用能力验一次；同组换题、换agent、换批次或下游失败不重开专项。

新增阻断必须说明“实际消费者、失败/缺口证据、最小修改、验收出口”。缺口解除、安装与现场资格齐备即推进合法业务，不追加同条件演示或无关优化。等待期仅推进原授权内有具体产物的独立工作；不等无关unknown清零。

用真实结果衡量进度：测试数、阶段名和Slurm完成不替代业务与收尾；少读、少复制、少启动需实际调用计数，速度结论需运行耗时。权限、数据隔离、未知动作、必要收尾及原整体/训练门保持。实操见执行指南（workspace 材料，未发布），不另建审批或检查平台。

<a id="evidence-checkpoints"></a>

### 每组、每题的必需预处理：证据检查点

**适用于所有实验阶段：已通过且对本次输入、版本、环境和状态仍适用的检查点，默认复用证据及可消费产物，不重复提交实验；只执行失败、新增、受影响或确有证据缺口的部分。** 后续阶段失败不自动撤销前序通过，也不意味着整条流程重跑。

接手完整组、每次选择成员（新题或未完成旧题）、变更或提交前，必须在原group/batch-plan核对检查点和复用范围；新题与旧题均不得省略，这是原开发循环的预处理，不是新增串行验收阶段。同组换题采用“组级证据复用＋题目差异检查＋现场必要核验”，不默认重建整套来源资格。一组只维护公共项，每题引用公共项并记录参数/分支差异和本次run/attempt事实；未执行成员不复制相同表格。后续任务族和构建/复验/导出/训练消费者按其原合同使用，不适用项说明理由，不改变原阶段门。

**必要预处理的最小交付是一份本次提交差异，不是重跑检查点表。** 在原清单一次核清本题身份/split、公开输入和合同分支，所选源码/配置/安装及已验分支的适用性，来源产物的实际消费方式，剩余准备＋完整执行＋收尾预算，以及资源隔离和恢复责任。静态可判断项在昂贵副作用前完成；当前owner/claim、实例初态、运行权限及动作前监听等现场项明确留在原运行时门，不能由静态预处理代替。无变化且证据适用的成员直接进入本题现场准备和执行；只有具体变化、失败或证据缺口才触发开发/补测，补齐后回到同一执行路径。每题仍独立取证、判定/复核和恢复关闭，不再为“预处理完成”新增证书、作业或整套验收。

**选题默认优先未完成旧题。** 先核本组旧题的原attempt、claim、已完成产物、未决动作及恢复关闭回执；在原授权和合同允许接续的旧题中优先推进，从最早缺失或失效的必要检查点补齐，适用前序产物继续复用。优先旧题不等于自动重放、重领claim或跨作业中途恢复；有效失败不为取正重跑，unknown仍按原规则隔离。旧题暂不能合法接续时，在原清单保留其证据、具体阻断、最小下一动作和解除条件，再选择已就绪新题，不等待全部unknown清零。每次选新题均在原提交计划说明未接续旧题的依据；换题不关闭旧题待办、不替代原题结果，也不免除新题的检查点预处理。后续每次选题重新核对这些遗留项，不复制另一套清单。

共同版本、依赖及复用/失效条件在组级登记一次；成员只记`状态｜本题差异/实例｜证据引用｜下一动作`及观察时间，其余引用共同项。状态用“未开始、进行中、通过、失败、未确认、不适用”，执行方式注明本次执行或复用；保留原验收事实及当前适用判断，不把复用写成本轮重新执行通过。

| 检查点 | 归属与依据 | 后续失败时的处理 |
|---|---|---|
| 源码安装、依赖与不可变资产 | 固定源码/配置/环境，原manifest、摘要和安装/消费者回执 | 精确范围未变即复用；节点/tmp和模型驻留另核，不能假定跨作业保留 |
| 全组参数与必要语义分支 | 原逐题映射、绑定与分支检查回执 | 每个新题核一次题号、公开目标、起点、目标参数、schema及已覆盖分支；纯参数变化不重跑模块测试，新增语义只补该分支及受影响消费者 |
| 组级共同能力与入口组合 | 固定合同/实现/配置，安装、接口、浏览器及初始化／判定／恢复分支的共同验收回执 | 对应源码、依赖、配置、环境和合同未变且覆盖仍适用即复用；变化只补受影响范围，不因换题、换批或末端失败重验整套框架 |
| 来源产物及必要补建 | 本题完整来源产物或明确与题目无关的共同准备；原引用、版本及适用范围 | 本题已有合格产物直接消费；仅有共同准备时复用共同部分，补本题绑定和必要初态证据；缺失、错配、失效或新语义只补对应部分，不因换题重建整套来源 |
| 现场状态与权限 | 当前实例、owner、claim、必要初态、独占权限及恢复责任 | 每题及合同规定的运行时门核实；历史产物或共同能力通过不授予当前动作权限 |
| 任务初始化 | 分开记录共同配置/准备产物与本题原attempt/实例、唯一观察及baseline证据 | 共同检查按精确适用范围冻结复用；新题/新实例只补绑定、现场初态及合同要求的事实，不因实例身份变化重验整套静态准备。失败先定向验证实际producer→consumer及收尾；不由旧初始化通过推断当前实例初态或续跑权限 |
| Actor执行与轨迹持久化 | 原attempt、请求/动作、返回与完整轨迹 | 已完成动作不重发；未决/未知动作按原账本隔离，不能从表格推断可续跑 |
| 判定与独立复核 | 原轨迹、证据及判定/读取器版本；两项可分行 | 原完整持久证据足够且合同允许时，只补复核和受影响检查，不重启网站/Actor |
| 恢复／安全Reset | 原可写实例及恢复前后证明 | 证明原实例状态；证据不足保持未确认，不以新实例或进程结束代替安全恢复 |
| 资源关闭与最终登记 | 原资源/账本，物理终止及关闭/登记回执分别记录 | 已证明关闭但登记失败时，只走原允许的登记核对；不得重复物理动作或伪造closed |

<a id="checkpoint-feedback-loop"></a>

**任务结束后的反馈必须回到下一次提交：收原回执 → 分析结果及首错/清理错 → 更新检查点与适用性 → 按新状态复用/补齐 → 提交。** 成功、有效业务失败、工程错误、取消/超时和未确认均执行此循环；这是原清单的维护与接续，不是额外作业或全组串行验收。

1. **按事实收结果。** 沿原job/run/attempt收来源、初始化、请求发送、原始返回及持久化、判定/复核、Reset、物理关闭与最终登记的回执，分别更新，不能只抄Slurm终态或汇总计数。已有原始返回但完成登记失败时，分别记录“返回已留存”和“核验/登记未完成”，不把整个Actor记成未执行；关闭和Reset无证明时保留未确认。获取/准备未返回或主流程失败仍须触发原有界收尾，不能等本次分析完成才关闭资源。
2. **更新原检查点再决定重做范围。** 在原group/batch-plan按原有字段登记新证据、观察时间和下一动作；组级共同项只维护一次，成员记本题差异。原通过事实与“对所选下一版本/成员是否仍适用”分开：失败或变更仅沿实际依赖使受影响适用结论待核，说明原因，其余继续复用。新修复/验收用新引用，原失败、unknown、claim和费用证据保留；更新当前摘要，历史提交快照不冒充当前状态。成功且闭环完整者接续下一成员，有效业务失败如实保留，不为取得正结果重跑。
3. **从新状态选最小合法动作。** 优先核原题是否仅需补核、补登记或独立复核；已有返回不重发。确需实际执行时按下文来源消费规则直接消费适用且允许消费的本题产物，只补缺失/失效事实。产物存在但消费者缺接线先修接口；缺当前资格、原实例或未决动作处理能力时登记具体阻断，不能因检查点通过宣布可中途续跑。只修失败节点及受影响组合，修复后将新验收和安装回执回填适用性，不重跑未变化前序；不等待无关unknown清零。
4. **下一次提交使用更新后的差异。** 根据最新检查点生成/刷新原提交差异，列完整复用引用、最小补做及原因、本次执行或补核入口、要补的真实结果；核最终源码/配置/安装、实际来源消费分支、当前资格及预算。共用修复逐个核实际受影响消费者的当前冻结版本、已验/已安装版本与所选后继，暂不切换须说明原因。分析后若又有新回执、修复或版本变化，只刷新受影响差异，不沿用失效计划、不整表重验。已提交输入保持冻结；是否替换仍按原作业及唯一后继规则。没有具体变化或证据缺口，不追加测试或安装验收。

检查点仍只是原回执、RunJournal/ResourceJournal/请求账本的索引和可读视图；冲突回到原证据核实，不建第二套权威状态系统。检查点更新不授予权限，也不把历史失败改为通过。

<a id="frozen-stage-debugging"></a>

### 阶段式调试的直接执行方式

先定位失败消费者，再选择最近有效输入；沿现有入口补缺口，不先建设独立调试平台。下面是工作划分，具体入口和产物引用记录在原组清单，已有实现直接使用。

| 调试位置 | 直接使用的输入 | 通过后保留什么 / 如何接续 |
|---|---|---|
| 来源与共同准备 | 固定任务来源、配置和已准备资产 | 兼容的准备产物，供组内成员复用 |
| 本题初始化 | 共用准备、本题参数和实际实例 | 目标绑定、初态证据及环境保留/恢复条件；证据不能代替活实例 |
| 候选/Actor 与取证 | 公开输入、候选 Skill、合法环境 | 模型返回、动作/观察和执行证据；已保存结果不重新请求 |
| 判定与独立复核 | 同一尝试的页面、状态、产物及判定合同 | 逐项结果；解析或判定代码故障优先离线重读证据 |
| Teacher 修订与 Actor 复验 | 已有候选、完整轨迹和允许的反馈 | 修订结果和新验证尝试；已保存响应直接复用，未知请求先核状态 |
| 目标导出与 SFT | 合格尝试、来源和数据划分 | 独立复核的数据、训练输出；导出失败不重跑网站，训练恢复按实际 checkpoint 能力 |

这些是数据依赖边界，不要求每题重复走所有阶段，也不要求为每阶段提交独立作业。Teacher 修订与 Actor 复验沿原流程循环，必要收尾贯穿每次实际尝试。

**一次修复的出口：** 当前失败已复现或明确定位 → 最小补丁 → 失败路径和受影响消费者检查通过 → 接续原批次。若需要串联实证，用下一次正常业务完成，不增加同条件演示。旧基线仍有效时，不重复冻结、不重跑前序测试。

**把方案落到代码的方式：** 当前入口缺少已有产物消费、阶段选择或恢复接线时，在现有端口/脚本中补最小能力；受影响测试确认真实消费者取得原产物、有效前序生产者没有再次调用。入口仍需活环境且不能恢复时，补必要环境准备并如实标明，不能声称实现了跨作业恢复。每修一个实际缺口就继续业务，不等待所有阶段接口一起完成。

**A 通过→冻结代码、完整产物及必要环境基线→B 直接消费并独立调试→B 通过后冻结→推进 C。开发期间，已通过且仍适用的前序阶段不再执行，其测试也不重跑；全部适用阶段通过后，才考虑一次必要全流程协调验证。**

1. **冻结可直接进入下一阶段的基线。** 在原清单引用代码/配置/依赖、完整输入输出及引用、原身份、验收、适用与失效条件，并注明下一阶段实际入口、所需环境状态及保留/恢复方法；不能只有 passed。已有合格基线直接采用，不为重新冻结另跑生产者或测试。优先原保留产物；必要工程夹具符合真实 producer 合同，派生链保留标记，不作原题资格或训练样本。
2. **只调当前阶段。** B 的独立入口直接调用生产消费者，缺接口先补现有端口；缺输入/版本或范围错配在副作用前拒绝，不隐式重启 A 或全流程。失败从最近有效开发基线恢复 B 的起点，只修改和验证 B 及实际受影响接口。未变前序代码及依赖保持原身份，不能混入任意旧树；只有具体变化使 A 的接口/假设失效才补 A 的受影响检查，B 失败本身不撤销 A。用受影响检查证明前序生产者零调用，并在原检查选择中记录前序测试复用；不另建一套“确认跳过”的验收。B 完成本阶段适用正常/故障检查且输出可消费后冻结，再推进下一阶段。
3. **收敛为有限修复批次。** 批次按共用缺陷、兼容版本和受影响消费者划定，不按每道题重新启动。固定代表题逐阶段调试；后续兼容题直接消费已验代码与共同证据，只补本题差异、现场事实和真实结果，只有新缺陷或未覆盖分支才补受影响部分。先按现有代码和失败证据确认本批真正要改的接口、预算或收尾逻辑；已有实现和有效测试直接复用，不把阶段表中的可能缺口都重新开发、验收。冻结前序上只修当前缺陷，运行失败节点及受影响测试；失败留在当前阶段，不启动整条业务链。最终协调并入这些接口测试与提交前安装一致性核对，不单独开展一轮工程。代码与适用测试全部通过、安装一致后，刷新差异及现场资格，进行本批必要的一次真实实例验证，确认串联、实际效果和收尾；阶段冻结不增加每阶段一次真实网站实验的要求。收原回执并更新检查点，通过即结束本批，有效业务失败如实接受，不为取正结果重复运行。共用实现验一次，Map/Admin 等入口只核实际差异；原整体 Review/显式全回归和训练门仍保留，不下放为每批修复的前置。
4. **结果反馈到原检查点。** 阶段通过随即记录冻结输出和下一独立入口；全流程结束收原回执→分析→更新 checkpoint→选最早缺失/受影响阶段。已有返回/动作不重发，工程失败回该阶段，未变前序继续复用；有效失败不重跑取正。各消费者取得自己的必要业务证据。“一次”不是永久额度、每轮题数或并发上限，不删除/重置冻结意图和防重复记录，不换 ID 绕过 unknown。

开发基线不冻结动态权限：完整性、范围及当前 owner、claim、撤权、锁和账本在必要边界核验，不因此重验整套静态前缀。活环境按已有生命周期保留或从已证明可恢复的隔离状态恢复；旧PID、会话号或checkpoint不授予跨作业接管权。缺恢复能力列具体缺口并补最小必要环境准备，不能宣称已能独立进入，也不默认重建整条来源链。每次尝试的现场清理当次执行，不能等到最后调试关闭阶段；已提交输入保持冻结。具体入口、状态恢复和阶段出口见阶段实施方案（workspace 材料，未发布）。不新增全局缓存、通用runner/checkpoint或恢复平台；下文及指南的“检查后执行”均受本门约束。

<a id="reuse-driven-execution"></a>

**所有后续题目（包括Map、Admin及其它网站/任务族的新题和未完成旧题）都必须落实：已有产物发现 → 差异决定执行分支 → 初始化已核正文传递，并验证复用项没有再次执行。** 以原兼容范围决定复用；各消费者在自己的下一次提交前接通适用链路，不等待全题池统一改完，也不因Map已接通而默认Admin或其他入口已完成。实现、软件验收和实际运行事实分别记录，以下要求不代表能力已经接通。

**证据复用不授予旧任务重放权限，Admin同样不得直接重放。** 原模型/浏览器返回已保存但登记未完成时，先按原claim、attempt、未决动作和恢复证明判断能否合法补核/补登记；缺续跑权限或接口则保留具体阻断，不重新生成、不重发已完成或未知动作，不通过更换ID绕过。下列入口要求只决定合法工作中的复用与最小补做，不能替代原动作账本。

1. **提交前自动生成差异清单。** 沿现有group checkpoint和原回执生成“**复用哪些、补做哪些、原因**”及精确证据引用，登记在原提交计划/意图；比较合同、实际源码、配置、依赖/环境、初始化及恢复分支，不能只凭网站或组名判断兼容。每项重做须说明具体变化或证据缺口、原条件/产物为何不足及最小补做范围；下游失败、换题/批次或脚本默认从头执行均不构成整条重跑理由。限定训练范围和最终整体门的显式全回归仍按原规则执行。纯参数核对与逐题现场权限/初态/结果/收尾仍保留；未核内容如实标未确认，不把表格通过当运行授权。已提交输入保持冻结，补登记的回顾视图须标明生成于提交后，不能冒充当时的准入检查。

   可用只读工具`python3 tools/development-checks/show-group-checkpoints.py --plan <原清单路径> --member <本次成员键>`生成表格及提交差异；默认读`/group_execution_plan/evidence_checkpoints`，嵌套清单显式传`--pointer <JSON指针>`，`--json`供原提交记录消费。默认只整理已登记适用性和路径。所选冻结版本已提供条件核验时，在Slurm用其已验工具和检查环境加`--verify`：按原公共项`verification`中固定的回执、源码文件范围、环境身份及输入文档摘要比较实际条件，输出具体变化、逐题参数检查和最小补核范围；同次正文只读一次。外部runtime调用方由`external_sources`引用同一检查作业的runtime-inputs接受及前后回执，再比较所声明文件的当前字节；core清单不代替外部入口核验。公共项的`member_inputs_required`须由本题`condition_inputs`提供当前完整引用，只能替换当前输入，不能改共同基准或参数白名单。新/缺字段、类型、schema或布尔分支变化不能作为标量参数差异忽略；公共前置未通过、适用性未核或映射/证据不足均返回未核与非零。原通过事实保持，缺映射只补映射/核验，不因此重做实验。此结果仅覆盖声明范围，不核现场权限、claim或实例初态，不调度/续跑、不改账本；实际消费者仍须核原回执、当前控制器及逐题资格。

2. **下一次执行前，优先核并直接消费已有本题来源资格产物，禁止默认重新完整构建。** 新题和未完成旧题都核已有产物、适用版本、合同、完整引用及当前消费资格。来源通过不等于允许再次领取：须逐项核原claim是否已消耗、产物是否依赖已关闭实例，以及合同是否支持再次消费，具体限制不能概括成“必须重做全部来源”。已有模型返回先保留并核能否独立补核、合法补登记，不重发请求。再查本题产物及适用范围：已有本题合格来源时，核完整引用、版本兼容和消费权限后进入后续初始化；仅有共同准备时，复用明确与题目无关的部分，只补本题绑定和合同要求的现场事实；需要新语义或特殊状态时，只执行对应新增或受影响分支。区分“必需事实确实缺失”和“产物已存在但入口不能消费”：前者列最小补建事实，后者列实际消费者的接口或权限限制，不能用“新attempt无来源”概括。来源/执行实例仍须按合同各自建立初态、恢复责任及关闭事实，组级产物不能替代。共同准备保留完整来源和消费条件，不换题号重造旧baseline/资格回执，不仅凭相同起点判定初态相同。入口若仅支持原owner/controller消费，应如实限定复用范围；不得删身份检查来接管历史产物。产物完整、适用且允许消费而入口未接通时，须先补现有消费接口，不得用下一次长时运行绕过缺口；合同不允许复用的事实保留必要构建并逐项说明原因。每次提交清单列明实际复用的完整来源引用、仍补哪些事实及补建原因。配置和清单只决定范围，运行入口及实际消费者必须接通这些分支；未接通时不得宣称已复用，也不得在下一次提交中默认整套重建。

   **提交差异必须决定实际分支。** 沿原任务映射、组清单和已索引原回执查找完整及部分产物；未完成检索记“待核”，不能硬编码空列表或用无claim/新题号证明无产物。原入口按差异执行复用、最小补建或必要完整构建；未说明具体失效/缺失依据，不得默认完整构建。已判定复用的项不再调用原检查/构建生产者，消费者直接接收已核引用和可消费产物；接口缺失或实际分支与差异不符，在启动对应昂贵操作前拒绝，先修接线，不静默回退重跑。这只约束受影响操作，沿用现有提交/运行入口，不新增审批或平台。

3. **同次调用链只读取一次已核验的不可变正文。** 来源准备、初始化和后续消费者传递完整引用及已核验正文，优先使用已有整图读取能力，避免各层重新遍历同一证据图；动态权限与账本状态仍现场核。具体边界按[证据交换优化方法](#runtime-evidence-optimization)执行，不新增全局缓存或常驻worker平台。

4. **模型／服务共享单独接入。** 先完成来源证据复用和必要检查拆分，随后在已有生命周期中支持兼容成员连续运行，逐题隔离或可靠重置；共享不作为上述改动的前置。单成员入口、连续共享及跨作业恢复按实际能力分别登记，检查点不增加这些能力；跨作业中途恢复仍须另行证明。

上述有限改动按以下出口验收，完成受影响检查、精确安装及实际消费者核对后进入合法业务运行：

- 相同版本的兼容新题只增加参数检查和本题必要证据，不重跑已覆盖的共同模块测试；用生产构造器/消费者的受影响检查证明被复用项的原检查/构建调用数为零，且有效产物确实被消费。改变一个依赖只补受影响项；新实例仍触发必要现场门。
- 错题、版本错配、权限失效及证据缺失会被正确拒绝或要求最小补建。
- 受影响接口、取消、部分失败和关闭检查通过。
- 随下一次正常业务在原回执记录实际复用引用、补做及原因，与提交差异核对，并记录读取／worker次数与准备耗时；不能只凭计划写“复用”判通过。不另开整条网站计时实验或同条件演示。

证据复用与执行恢复分别验收。新实例或变化的动态状态仍须建立本次必需条件和恢复责任，与重复软件验收分开记录；不继承旧owner、失效权限或已消费claim，不承诺免除全部实际准备成本。默认只在题目判定、必要落盘、恢复和资源关闭完成的边界接续；同题跨作业中途恢复必须另有原实例身份、持久状态、独占权限、恢复和未决动作处理的真实能力证明。

### 运行批次、时限预算与安全接续

**完整组集中开发，在题目完整收尾边界接续。** 本节是同一开发循环的执行规则，不新增预算分析阶段、调度器或通用断点平台。先核入口实际支持单成员还是多成员；可复用预算机制不代表连续多题共用模型/服务或单题跨作业恢复已经实现。

- **共用框架。** 保留总期限，在其内显式分配来源/资产准备、本题准备、初始化、Actor、取证及判定预算，另留独立且有界的恢复关闭窗口和硬截止余量。开始新工作须保留完整选定核心调用及后续必需落盘/收尾；前置检查额度是上限，可在上述保留后按实际剩余收紧，不要求每次都能耗尽全部检查上限。不能每进入一阶段就重新获得完整总预算。所有子操作沿用原身份及父期限，单次证据操作取自身上限、阶段剩余及父期限的最小值。Actor保留完整选定执行预算，不靠压缩64K/O4096配置适应准备后的余量。延迟确定首次获取期限时，冻结声明与实际入口须共用同一获取身份；同时核operation/resource谱系，不能只验秒数。停止信号、内部deadline与Slurm时限须一致，不能让应用仍允许运行而Slurm已强杀。只修实际消费者所需机制，不扩建通用恢复范围。
- **各阶段检查与执行分离。** 来源/资产准备、模型获取、本题准备、初始化、Actor、取证、判定/独立复核、恢复关闭及后续构建/导出/训练消费者均按实际组成区分：前置准备/准入检查、核心工作、结果核验/保存。可独立且有明显开销的检查使用单独有界预算，不能预先消耗明确分给核心调用的执行窗口；所有部分仍计入阶段、任务和作业总期限，按串并行关键路径组合，不重复累计嵌套计时。轻量内联身份/取消检查可留在执行窗口并注明，不为每个函数新建计时器；完整性校验与复制不可分离时如实声明组合预算，不暂停执行时钟掩盖耗时。来源资格、判定、复核及Reset证明本身属于必要核心工作，不能因名称含“检查”当作冗余删除；没有独立前置或实际调用的部分记不适用，不强造两个阶段。主流程开始前及实际派发前核剩余完整调用、必要后续落盘与收尾预算，不足则不启动新副作用，不静默压缩选定执行窗口；已发生副作用仍须有界收尾，不能因检查超时跳过必要关闭。统一审查口径随实际消费者增量落实，不等待全部阶段重新验收，不新建预算平台。
- **内层请求与动作的接线。** 每轮动态authority核验、请求准备/计数、发送前核验与意图登记均纳入明确有界的准备/检查额度，不得在建立该窗口前无界消耗Actor总时间。准备前先保留完整模型执行窗口和必要返回保存、动作及收尾余量，再将本轮准备上限收紧到配置上限与可用余量的较小值；真正派发前再次核余量。模型或浏览器调用在最后必要准入通过、真正派发边界取得完整选定执行窗口，返回证据另有有界保存窗口，均受原父期限限制。准备额度不足则停止准备且不发送，不缩短模型窗口、不延长原期限；调用次数上限不保证每次均可耗尽最大时限。沿原端口及一次性意图协议实现，外层事务上界、请求身份及原输入先固定；派发处仅允许经验证的一次性子窗口，不延长已登记operation、不重发原意图，不省略必要动态权限门。确定未发送的预算停止须与工程异常、模型执行超时及发送结果unknown分别记录，保留已完成返回/动作和未完成业务状态，进入独立有界收尾；预算停止不证明Reset、物理关闭或最终登记。旧版本仍共用期限时如实标注，不能只改配置名就宣布分离。只补受影响的慢准备/慢核验、正常调用、余量不足不发送、取消、已发未回及返回保存失败组合；原未受影响证据复用，不扩大恢复范围。
- **网站/兼容任务族。** 按合同、源码、依赖、环境及资源配置，用已有记录设置准备、执行和恢复预算；不同网站不要求相同秒数。区分完成耗时、失败/超时记录与估算，冷/热准备分开，嵌套区间不重复相加；样本不足注明依据和不确定性。按实际串并行关键路径加必要收尾和合理余量确定作业时限，不机械套用6小时20分钟或为排队任意压到1小时；`Priority`本身不能证明时限是唯一阻断。
- **具体题目。** 使用所属配置，在正常业务执行中记录实际耗时并逐步调整任务族预算；只有新增语义、特殊资源需求或明显异常才单独分析。不等待全题耗时样本，不新增逐题计时实验或预算验收，不以寻找最优时限阻塞已就绪成员。
- **准备前移并精确复用。** 配置/schema、路径、预算一致性、固定安装和只读资产核验提前完成。只跨作业复用已持久化且消费者能核验的产物；prepare-only按实际副作用处理。原owner、动态权限、claim、实例初态及另一节点/tmp不能当通用缓存，可写状态保持隔离。
- **有限修改出口。** 补齐领取前“后续准备＋完整任务＋必要收尾”检查后，只验证受影响接口、预算组合和超时/取消/部分失败收尾，完成精确安装及消费者核对，随即回到原资格下的实际题目执行。复用未变化证据，原整体门保留。新增阻断须说明实际消费者、失败证据、最小修改和验收出口，不把全部预算分析完成设为前置。
- **按完成边界合批。** 已有合格批次入口时，兼容成员按预计时长及资源复用模型/服务/只读准备，不机械固定题数。每题独立保存结果、取证、恢复和关闭证据；不足以完成下一题及必要收尾就结束本批，未执行成员待接续而非失败。单成员入口如实保留，不为缩时把单题拆成许多作业。
- **不默认中途续跑。** 默认接续边界是本题判定、必要证据落盘、恢复与资源关闭完成；批次共享资源按合同留至本批结束，退出作业前关闭。单题跨作业续跑须证明持久状态、原实例身份/独占权限、恢复及未决动作处理，不能强杀后猜测续跑。完整证据落盘后，独立只读复核可在原合同和端口允许时交CPU作业；完成前不记完整验收/训练合格，也不能推迟必须现场完成的取证或关闭。
- **冻结与等待。** PENDING输入仍冻结；调整或替换依[调度协议](#scheduler-wait-protocol)核原作业、精确版本和唯一后继，不原地改冻结部署或重发原尝试。unknown不自动重放，有效失败不为取正重跑。等待时收终态回执并推进下一组无冲突的独立工作，原授权、隔离和训练阶段门保持。

每组沿用原包一份计划和一份汇总：在已有成员/分支/依赖/检查字段登记预算适用范围、精确复用依据、实际执行粒度、剩余具体阻断及验收出口。分段耗时、估算明细、运行流水和完整报错留原包或独立报告。区分配置调整、代码支持和已验证行为，不凭方案承诺排队或运行缩短幅度。

## 交付范围与真实依赖

### 运行等待期继续准备下一组（2026-11-03）

提交长时运行后，默认推进“当前组运行 + 下一完整兼容子组准备”，不把当前作业终态设为无依赖准备工作的前置。先保持一个明确的下一组，避免扩展成全任务池重新分析；这些是同时推进的工作，不增加新的串行验收阶段。

- 从已有全题范围表选下一完整兼容子组，核原合同、版本、初始化/判定/恢复差异及当前消费者，登记可复用证据和有限缺口；保持完整成员映射，不跨子组抽题拼批。
- 在现有组清单登记参数绑定、必需来源/资源、精确新增测试节点及复用依据。已有能力覆盖的成员直接准备数据；新增语义集中开发。资料含私有规则时不进入模型输入，dev/test仍按原门。
- 活动作业的源码、入口、配置、数据pin和共享可写实例保持冻结。需要编码时使用独立候选/工作树及独立可写输出，不回写活动输入；若依赖当前作业尚未验证的接口，只做不依赖结果的部分，记录明确等待项。合并前核最终release与受影响回归。
- 无依赖的新模块检查可按原资源规则提交；下一组真实执行必须满足自身来源、权限、隔离、接口证据及原预算/并发限制。不能把准备并行理解为自动增加付费并发或共享同一可写网站；付费同授权上限仍为1。
- 按上文调度观察时限或状态变化检查当前作业，异常当轮处理；正常运行期间轮询不是唯一工作。当前结果到达后，只把实际影响下一组的变化纳入修复与复测，不重做已完成准备。
- 每次进度汇报同时列“当前运行到哪一步、下一组已准备什么、还依赖哪个具体结果”。若确无可推进事项，说明具体依赖/资源冲突，不能只写“等待本组完成”。沿用本包清单和汇总，不新建等待期审计或交接阶段。

**合并执行，减少往返。** 同一有限改动批次优先在一次Slurm作业内顺序完成便宜预检、所选测试/静态检查和必要安装读回；仅因资源、冻结边界或失败诊断需要才拆作业。格式化在冻结前完成；冻结后不边测边改。源码小改用现有增量类型检查，同冻结静态验一次；测试/夹具变化只核其影响。工具暂不支持精确范围时合并一次现有检查，不为节省检查另建平台。

**把可提前发现的装配错误放在昂贵资源前。** 利用冻结输入和真实消费者核来源/当前owner分支、上下文绑定、终态读取器及未注册资源的失败出口，合入受影响接口测试；不靠加载模型、启动网站发现可静态复现的错配，不另开同条件长流程演示。动态owner/claim、撤权和现场初态仍在真实动作门复核，离线检查不授予权限。

失败保留原回执，修后先跑失败节点，再补尚未覆盖的受影响部分；刚通过且未变的节点不重跑。只修测试/记录脚本不重跑生产实验；记录失败只补记录，软阈值不制造业务失败。必要检查、安装和当前资格齐备即推进实际执行，不追加无具体缺口的审查或“验收的验收”。

原最终整体Review、显式全回归及训练门保持原范围。逐题实际结果、判定/独立复核、恢复关闭必须取证；运行正文复用按[证据交换规则](#runtime-evidence-optimization)，兼容组服务共享按[运行批次规则](#runtime-batch-budget)。

### 重复检查与证据交换的优化方法

每轮围绕已有失败，在原包明确有限的实际闭环主线、一组等待期间的必要准备及共用缺陷修复范围。已授权且资源、可写状态无冲突的任务/网站组可并行；已证实阻断当前消费者的缺陷才列为提交前置，其他效率改进随正常业务取证，不追加优化专项门。未变化证据直接复用，检查范围按[最小检查表](#change-evidence-scope)选择。具体网站和优先级只记原包，不新增串行验收阶段；后续原定多来源组合保持。当前输入冻结，修复放隔离候选；同一根因集中修复，已知共用阻断未解除前，不提交另一个依赖它的成员反复调试。

**检查频率按被检查对象的变化范围确定，不能把每个阶段、每层权限门或每次换题都当成重新验证全部依赖的理由。**

| 对象 | 复用范围与必要检查 |
|---|---|
| 软件验收与固定安装 | 精确版本、依赖、配置、环境适用即复用；运行时先减少worker和逐叶交换，使一次完整安装核验服务一次有界整图消费。新进程现行安装身份检查不能靠旧passed或可写路径直接跳过；进一步合并须证明受控安装/worker生命周期与失效检测 |
| 不可变证据正文 | 同一次来源或任务入口内，首次按完整引用核哈希、schema、依赖，后续实际消费者复用；包括准备→初始化→Actor准入，不能在组件返回时丢掉正文后逐层重读。新引用、明确失效和合同要求的准确发布读回分别核；新生成对象仍校验完整性 |
| 组内来源共同产物 | 按合同、数据版本、初始化/恢复分支和实际环境复用；本题只补绑定和必要现场事实。“新attempt没有来源”或“未登记索引”须先核已有产物及缺失字段，不能直接触发整套来源重建；清单必须记录实际消费者所走的复用或补建分支 |
| 动态权限和本题事实 | 当前owner/claim、撤权、资源、轨迹/账本状态、唯一初态、结果及恢复仍在相关门核验；获取当前事实不得无理由连带重验全部静态正文 |

再次提交前，用保留产物和生产构造器覆盖已知受影响的完整消费链，包含首次模型请求的派发边界及失败收尾；验收调用次数、复用分支和正确拒绝，不以单个函数少读几次或进入actor阶段代替。已有精确证据复用，不额外要求全套网站演示；达到本轮有限出口即恢复合法业务执行，不继续扩建优化平台。

1. **先沿引用找调用方。** 从原运行记录按完整EvidenceRef、操作/父操作和实际消费者归并读取，区分不可变正文校验、语义检查与动态权限检查。同一次调用链中，将已核验正文连同准确引用向后传递；已有完整图读取就复用，不让每层重新远程解析同一正文。调用链以一次来源或任务入口为界，退出即清除正文，不跨独立入口保留；当前消费者所需完整图只核读一次，发布后的准确回执回读仍保留。哈希、schema、身份及依赖关系仍须满足原合同，动态权限在相关门现场核验。跨调用或跨作业复用另须证明持久产物及消费者核验能力，不能继承旧owner、许可或另一实例初态。
2. **拆出每次交换的固定成本。** 分开记录派发与解析两段的准入、worker启动/就绪等待、请求/结果传输、持久登记/同步和正文处理；区分调用次数、不同完整引用数、重复次数与字节数。使用原有计时及可核日志；现有区间无法再拆时标明未知，再仅给受影响路径补必要计时。可用隔离工程会话核现有入口的固定成本，保留原模块身份、真实安装核验和持久登记；须注明夹具、启动方式、缓存状态及剖析开销，不当作生产耗时或运行资格，也不能用小账本结果排除增长账本的成本。减少次数乘以单次交换耗时只作成本换算，须以实际调用减少量和正常业务观测核实，不能记作已实现提速。嵌套区间不重复累加，不把总时长笼统归因于文件系统，也不凭单个样本先建设常驻worker或新平台。
3. **按实际消费路径做最小修改。** 准备器和消费者均核实际模块来源，声明搜索路径不能代替真实导入核对。优先消除重复遍历、传输及重新解析，保留每次必要准入、原持久登记、once/unknown和取消收尾。优先减少交换次数；能够沿现有端口交付正文时，不把持久登记或解析协议重写作为前置。获取意图、配置等正文复用必须匹配完整引用；各门仍现场核owner、资源账本、撤权和存储状态，引用变化或状态失效不得沿用。准备图已核验的正文和完整引用集合可在本次调用中交给后续检查；后续新增引用仍须读取，下一次调用重新核验，不为正文传递改写持久schema。检查同时含不可变内容和现场I/O时，内容可集中读取，现场操作仍交原权限持有者，返回前核原会话/版本与准入，不能把权限随正文委托。不可变正文与可变会话账本分开：正文已核验不代表账本仍可复用，不能据此跳过原锁、版本冲突或撤权检查。准入层向资源层传递同次来源事实时，只复用正文与语义结果；资源层仍核当前权限；返回前以同次完整正文及准确引用复核来源，并现场重核权限、claim、存储和账本，未适配端保留完整重读。传递对象不独立授予动作权限，不跨调用保留。同次文件核验可向复制器传递已核目录/元数据，保留全组前置检查、逐文件身份/完整性及末尾整树变化检测；独立复制调用仍自行前检。正文已边读、边哈希、边写时不新增一遍预哈希；最终权限可在原独占句柄上设置后同步，完成文件的耐久性不减。有界并行须由整次暂存共用有限队列，动态权限、账本及最终登记仍串行；首错停止领新任务，等待原写入停止后再收尾，未全部核验不得发布就绪。复用已哈希内容仍须覆盖原完整范围，保留身份、权限、前后变化及关闭检查，不能变成跨调用信任缓存。修改前在原包列明三类证据范围；同一合同的参数变化复用共同检查，新增语义只补对应分支与受影响接口，不以增加超时替代根因修复。
   跨实例资产复用须按实际读写用途划分：已验不可变副本可由原作业生命周期持有，输入与真实消费者显式接通，各实例现场核权限，全部消费者关闭后才释放；可写数据须独立或证明写时复制隔离。先用目标文件系统小文件核能力，不支持则保留必要复制，不额外建设全量缓存；实际少读/少复制随正常业务核实。Map具体边界见[暂存合同](design/codebase-architecture-v1.md#map-stage-bounded-copy)。
4. **验收真实接口和失败组合。** 用保留证据或符合真实生产者格式的夹具，调用生产使用的构造器和校验器，贯穿来源产物、任务输入、初始化、Actor绑定及收尾声明；区分当前已登记意图和先前已完成产物，不能只测末端解析器或另写宽松检查。故障注入须命中实际外层发布合同及原对象，断言首错类型和失败阶段，不能把未到达目标门的其他错误当作覆盖。静态可判断的错配在网站/模型获取前拒绝，现场权限与实例初态留原门；新发现的共用故障先补入受影响组合。覆盖正文错配/缺失、撤权、取消及必要部分失败；初始化失败与随后收尾失败一并验证：原控制器独立有界地关闭其原资源，证据存储失效时物理关闭和结果登记分别退出，保留首错及全部清理错，未确认恢复/关闭仍记未确认。不得借此扩大通用恢复范围。
5. **以闭环出口停止扩展。** 原包明确实际阻断及消费者、可复用与必须重测证据、改变的昂贵调用链及次数依据、原初始化/收尾故障覆盖、下一次业务运行尚缺的真实证据。受影响接口与故障组合、精确安装及消费者核对通过后，直接进入原资格下的实际运行，不再增加同条件演示或无关验收。分别记录正确性（Actor开始、判定/独立复核/恢复关闭，可靠失败亦如实保留）、效率（Actor前耗时、交换/唯一引用/重复读取/worker次数）和复用（兼容成员只补参数及逐题证据）。夹具减少读取不等于生产提速，不为每处优化重启网站，不新建逐题计时实验或等待全题样本；未受影响证据复用，最终整体门保留。完整闭环前不承诺后续自动变快，模型/服务连续复用只按已有生命周期作有限增量接入。
6. **将方法留在同一正文。** 每次优化后把可泛化的做法、适用条件和失效边界原位合并到本节；其他操作文档引用此处。具体版本、改动、已执行/复用节点、调用次数、耗时、失败与未验证项放原包清单及其一份汇总，明细留原日志/报告。不得把某题秒数、局部成功或单成员入口能力推广为所有任务的保证。

## 检查入口与证据复用

仍由Slurm执行`cluster/check-framework.sbatch`，按文件/节点重复传`--test-first`。`--full-regression`只在整体门显式使用。`--exclude-passed-from /绝对路径/result.json`可重复传，要求framework-check/3整份回执passed=true、源码稳定、完全相同登记文件与环境身份，以及所选测试exitstatus=0和实际成功节点；不匹配报错。原失败作业内部分通过节点不得直接喂给这个自动参数；只能有据人工登记逐节点兼容复用并保留整作业失败。旧/2回执保留，可人工做有依据的影响分析，不被自动转换或当作新版本通过。

例：失败节点先用`--test-first tests/framework/test_x.py::test_failed`通过；后续同源码检查`--test-first tests/framework/test_x.py --exclude-passed-from <失败节点通过的result.json>`，只运行尚需验证的节点。明确选择不要全部被排除；pytest无剩余用例仍报错，不能空跑当验收。

工具代码位于tools/framework_checks：cache负责有界锁/摘要，environment负责冻结环境身份，static负责静态结果与Mypy缓存，selection负责已通过节点复用，pytest_reports记录完整setup/call/teardown状态；业务包不依赖这些工具。

- 静态结果按全部登记源码、配置和冻结运行环境身份缓存；相同版本分片共享一次Black/Mypy。回执逐项标executed/reused并链接原日志；原日志摘要改变、缓存损坏拒绝复用。只缓存静态成功且源码未变的结果，软件测试失败不抹掉有效静态事实。
- Mypy缓存按环境与pyproject身份复用，使用独占锁避免并行写入；源码小改仍执行Mypy，由其增量分析。`--fresh-static`强制执行；整体门也强制执行静态检查。缓存加速不取消类型检查。
- 环境身份绑定Python实际路径/字节、版本、冻结base_prefix、发行包版本/位置/METADATA/RECORD、独立Mypy内容及相关环境变量。**假定已发布Python/依赖目录不可变；这不是逐次重新哈希全部第三方库。**依赖更新须发布新运行目录，不能原地改包后沿用旧身份；调查环境漂移时用fresh-static并重新验证运行环境，安装缓存另用新命名空间。已有运行资产不可变规范继续适用。
- worker_install_cache按完整src、构建元数据、安装recipe和相同环境身份保存wheel与实际安装payload，冷构建核源码，热读取核全部产物摘要。原子发布只读产物，失败临时构建保留为诊断而不命中。每作业新建轻量venv并复制payload，禁止硬链接，安装后-I真实加载核来源与当前源码；可写状态与权限修改不会传播到缓存或其他作业。
- 缓存只为同用户开发检查加速，不是生产发布、运行权限或正式实验回执。工具缓存只写workspace/cache/framework-checks；每次检查仍有独立不可覆盖的输出目录。运行时限不因优化扩大。

## 汇报与完成标记

检查预算以实际冻结入口为准：本次核canonical tools/check_framework.py支持`--selected-test-budget-seconds`的300/420/600/3600，默认300，非默认值须有`--test-first`。3600是可选能力，不是普通模块默认或失败自动延时；使用时须在原包说明实际集成范围及预算依据，先核能否按消费者合理分片并保留完整组合证据。该选项不延长生产operation，不改变全回归600秒默认；回执记录实际预算，原失败/unknown保留。不同候选入口开工核自己的参数，不能照抄历史列表。

每次报告：复用了哪些检查点；补做了哪些及具体变化或证据缺口；入口实际到达阶段；Actor与完整闭环数量；剩余阻断及下一最小动作。未验证的环境与能力明确列出，逐题结果分别记录。可附测试时间、静态执行/复用和安装冷/热准备耗时，不能把排队、准备、测试、人工分析混算成单测慢。源码文件数和用例总数只作为审计附项。

软件优化通过不等于真实权限、控制面I/O、正式入口或训练全部通过。当前缺口按实际消费者和后继回执判断，原失败/accepted记录保持；不重复迁移/索引。历史补充映射需由实际消费者按原发布流程和读取测试接入，不能仅凭资料存在视为生产已切换。

静态夹具登记补充（4760384）：tests/framework/fixtures下JSON/text/binary等全部静态文件参与inventory；修改、增加、删除和置空都使旧通过记录失效，Black仍只收Python。新增静态测试数据须进入此目录或显式登记；外部冻结资产由其独立身份核验，不能直接复用未登记可变数据的测试结论。旧/3回执按当时实际登记范围保留。
