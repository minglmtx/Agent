# 文档用途、优先级与维护规则

本页是现行维护约定。清理文档不改变任务授权、方法、运行版本或验收结论。

## 日常执行只保留一个规则入口

先读当前 goal 和 AGENTS；执行细节只查[日常执行规则](FRAMEWORK_CHECK_WORKFLOW.md#execution-defaults)对应条目。架构、专项设计、代码指南和面试材料属于按需参考，不要求每轮加载。历史“下一步”、旧作业状态和设计验收矩阵不自动成为当前待办。

“每次校验权限、身份、预算”等接口合同描述程序在运行时的行为，不要求开发 Agent 在每步外加一轮人工审查、重新证明整个合同或请求用户确认。改动触及该行为才验证受影响实现；当前动作本身需要的现场校验继续由真实执行入口完成。

完成标准在当前批次开工时确定：范围、可观察产物及必要检查，沿用原清单；达到后继续下一批或交付。反思触发及停止条件统一引用日常执行规则，不在每份文档再维护一套提示词。

## 读取和裁决

| 材料 | 用途 | 不能据此推断 |
|---|---|---|
| goal、AGENTS、现行检查流程 | 长期目标、开发规则与阶段门；用户最新明确要求优先 | 已实现、运行权限或成功结果 |
| 架构和模块/专项设计 | 职责、接口、数据/状态与验收要求 | 文档列了组件就代表已部署；提案就代表已授权 |
| 原包current/plan、release manifest及原回执 | 核具体后继、源码/配置/依赖、真实结果与范围 | 单个passed、mtime或Slurm COMPLETED代表全链通过 |
| 有日期的报告、历史交接、候选副本文档 | 解释当时版本和原故障、查接口沿革 | 当时PENDING仍在运行；当时“下一步”仍应执行 |
| 分组表、逐题资料、迁移台账 | 参数、语义和来源的预处理参考 | 运行准入、授权、软件/业务或训练已验收 |

规范冲突按最新用户要求及现行规则核实；运行事实冲突须查原身份、后继和原回执，不能选更乐观的一份。接口版本以明确选中的release为准，不能用历史文档全局升级/降级。未核事实标“待核”，不要抄旧状态。

## 写入前先读

- 先确认本次任务确需修改哪份文档、该文档的职责和适用版本；阅读目标段落及相关上下文，再查已有同义内容和权威引用。按需读取，不默认加载所有历史日志或逐题资料。
- 有新增事实、规则变化、错误纠正或明确交付需要时才写入；仅阅读、轮询或重复确认不产生新段落。无关文档不顺手改写，不因个人表述偏好重排全文。
- 修改前重新核对目标内容，避免覆盖其他执行者的更新。无法确定原意或证据时保留明确疑点；不得擅自改变目标、授权、合同、阶段门或验收结论。

## 如何更新

1. 默认入口保持短：START-HERE只给阅读顺序；goal只给目标约束；AGENTS只给规则；handoff只给当前工作包、证据路由及必要下一出口；docs/README只导航。不要在这些文件反复追加作业号、测试数量、失败沿革和长段重复提示。
2. 优先修改所属段落并合并同义内容，不在顶部或末尾不断追加“最新补充”。同一规则维护一个权威正文，其他文档仅链接；明确被取代的旧指令从现行正文移出，不让新旧说法并列。已淘汰方案及重复的“不采用某方案”说明直接删除，正文只保留现行选择与必要边界；独有历史事实和验收证据仍按第4、6条保全。每次写入保持简要、清晰、原意完整；不得为缩短篇幅删掉条件、例外、否定、身份/版本、证据范围或未验证边界。
3. 状态只更新原包现有清单及一份简短汇总，注明观察时间、具体版本、证据、适用范围和未验证项。运行流水、完整报错、逐次尝试和历史进展单独放原实验目录；需人工说明时，在 `reports/` 按主题/批次维护日志或报告，注明时间和原证据链接。优先复用已有日志；不为每次轮询或每个小改动新建文档，也不把日志全文复制回规范。日志过长按批次/日期归档，当前汇总不累积旧状态，不另造权威账本。
4. 被取代的交接/提示词从默认阅读路径移出；原路径保留短说明和新入口。涉及独有事实/验收的原文先按原字节保存并记录摘要，不删除原失败/unknown/claims/费用证据。归档中的相对链接按原路径解释，不把归档当现行规范；普通措辞修正不必另建整份快照或长交接。
5. 含技术合同的模块文档可保留，但只按本次相关版本读取；旧进度不当当前指令。若修改接口，更新定义、所有实际消费者和对应测试，设计正文同步设计指针；文档修订号不是runtime release。
6. 不批改冻结源码副本、运行inputs、验收回执、逐题原材料或历史pin。旧版本描述只在其原版本有效，根入口明确隔离；实际消费者切换另有实现与验收。
7. 写后检查差异及最终段落：修改是否必要且限于本次范围，是否保持原意和关键约束，是否有重复/矛盾/过时指令，日志是否已分离；核相关链接、应同步的摘要和归档。检查通过才算文档修改完成。文档检查不运行软件/网站测试，也不宣称功能或性能通过。

## 高频文档与checkpoint的读写

目标是每次取得当前决策所需的完整事实，避免将历史全文、重复快照和原始大字段反复送入上下文。文件体积、行数仅作定位指标，不等于模型token数或召回质量。

| 材料 | 默认读取 | 写入边界 |
|---|---|---|
| 接手入口、当前摘要 | 当前工作包、权威位置、阶段、阻断和下一动作 | 原位替换过时状态，只保留短结论和证据定位；不累积逐轮汇报 |
| plan/current/checkpoint | 先取字段目录，再按group/task/run和所需阶段提取 | 当前选定版本、活动作业、未收结果、未决claim/unknown/恢复及下一动作；共用证据集中引用 |
| delivery-summary | 结果计数、适用范围、未闭环项、下一动作和原回执位置 | 从权威清单与回执形成摘要，不复制整块checkpoint、安装清单或完整测试列表 |
| 架构、设计、流程 | 标题/锚点定位后读取相关合同及必要上下文 | 现行规则原位维护；作业流水、历史修订过程及已替代方案退出当前正文 |
| 全题目录、映射、逐题资料 | 按明确site/family/task ID筛选需要的记录 | 保留原资料和冻结身份，当前清单只引用选中成员；不复制全题目录 |
| 日志、失败与验收原件 | 按引用核所需字段；诊断时读取完整相关异常链 | 原字节与证据身份保全，明细留原实验目录；摘要不替代原件 |

**读取：** 先看大小、标题或JSON键与记录数，再明确字段/章节和条件。超过64 KiB的文件默认定向提取；单次展示以8 KiB为软目标，必要合同、完整异常链可分段展开，不按预算截掉事实。提取结果注明来源、JSON路径/锚点、版本或观察时间及省略范围；空匹配、读取失败和输出截断分别报告。行数不能约束超长行或单字段，长字符串先报长度和证据位置，需要时再读原值。程序可以完整解析所需文件，但只把本次所需结果送入模型；大文件核验/归档重放仍按Slurm规则执行。

**复读：** 同会话内未变化的规范与已核不可变回执复用已有结论和定位。文件有新版本、相关字段发生变化、证据冲突或需要精确原文时，只补相关部分；接手/上下文压缩后先恢复当前短摘要及原引用，不默认重读整包。动态权限、claim、撤权、初态和现场状态仍在相关门重新核验，文档摘要不提供运行许可。

**更新：** 一个事实确定一个权威写入位置，其他清单引用路径、JSON路径/成员ID、所指版本及必要摘要。每个被观察对象只维护一个当前状态，历史变化沿原记录追溯；无变化的轮询不追加重复段落，必要的观察时间/下次复查原位更新。共用能力记录一次，成员只写绑定、差异和本题结果。测试汇总保留计数、范围、失败定位及原回执引用；长参数化测试ID保留短定位与原数组索引/证据引用，完整ID和参数留原件，不能丢失区分失败样例的依据。相同对象不在plan、summary和嵌套历史中反复展开。

**控制增长：** 接手入口及人读汇总以8 KiB为软目标；当前摘要超过此量、状态文件超过64 KiB、单字符串超过4 KiB，或同一证据出现多份展开副本时，先检查职责和重复内容。阈值只触发定向读取与整理判断，不自动删证据、不截断原输入、不新增执行门。完整目录/原始证据可以较大；每次修改检查新增内容是否属于该文件，禁止把工具完整输出直接粘入摘要。

**归档与兼容：** 已完成/被替代过程保存原身份、结果、证据位置及关闭结论后，沿原包归档，当前只留索引和仍需复用的结论。未解决的unknown、claim、费用占用及恢复缺口继续出现在当前待办，即使原作业已终止。字段改为引用或拆分文件前核全部读写消费者、活动输入与后继；消费端未适配时先定向读取，保留原格式。不得改冻结运行pin或账本历史来缩文件。

**并发与写后核验：** 写前重读目标字段并核版本，使用现有锁/版本条件更新或协调唯一写者；文件已变时基于新内容重做最小合并。原子替换本身不能防止覆盖另一写者。写后核JSON/Markdown、语义差异、引用/摘要、重复副本及字节增量；多份必需兼容投影记录相同来源版本，部分更新失败不得声称全部同步。文档整理不触发模型、网站或已验全流程重跑。

## 默认接手流程

读根入口→核原包及真实冻结→选完整兼容组→一次核共同能力/必要分支→集中实现并测试→已就绪成员随原入口执行并逐题收证据。等待时推进无冲突的独立工作。AB→ABC不等于跑完整AB题池；unknown处理不作为全局清零阶段；完整框架/训练和dev/test门仍保留。

详细检查/调度规则以[现行流程](FRAMEWORK_CHECK_WORKFLOW.md)为准，不在每份交接复制一遍。
